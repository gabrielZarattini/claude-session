O `platform_post_id` também **só é gravado se veio `scheduled_post_id`** no payload — publishes ad-hoc/pipeline sem esse id NÃO persistem o id remoto em lugar nenhum de `scheduled_posts`.

## Resumo executivo p/ o smart-delete

- **Onde está o id remoto:** fragmentado em duas tabelas (`scheduled_posts.platform_post_id` para o path `publish-social` de todas as 7 plataformas; `meta_posts.meta_post_id`/`post_url` para o path `publish-meta` de IG/FB). O smart-delete precisa consultar AMBAS. `platform_post_id` só existe quando o publish carregou `scheduled_post_id`.
- **Delete viável hoje por escopo já concedido:** Twitter/X (`tweet.write`), Pinterest (`pins:write`), LinkedIn (provável, via `w_member_social` — validar).
- **Delete que exige escopo NOVO (força re-consent):** YouTube (`youtube`/`youtube.force-ssl`, temos só `youtube.upload`), Facebook (`pages_manage_posts`, temos só os scopes IG).
- **Delete IMPOSSÍVEL via API (limitação da plataforma, nenhum escopo resolve):** Instagram (Graph não deleta mídia publicada), TikTok (Content Posting API não deleta vídeo publicado).
- **Fragilidade a corrigir antes:** TikTok grava `platform_post_id=null` em conta SELF_ONLY (perde o `publish_id`); threads do X só guardam o 1º tweet id.
