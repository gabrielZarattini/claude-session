- `deduct_mco_coins` is called with `p_user_id: user.id` (from the verified JWT, never client body), `p_amount: cost`, `p_action`, `p_context` — atomically **before** the Graph send (line 247), and the code checks `deductErr` → 402 fail-closed (line 253). A caller can only charge *themselves*.

- Order is correct: category resolve → consent gate → deduct → send → refund-on-fail. No charge if consent blocks.

**Window-gate / consent-gate:**
- `to` is derived from `conversation.external_thread_key` (server, from DB) when a conversation is bound — never the client `to` (line 164).
- Free-form text requires `windowOpen`, computed from `conversation.window_expires_at` (server-managed, DB-sourced). No `conversation_id` ⇒ `conversation` null ⇒ `windowOpen` false ⇒ 409. A client cannot send free-form to an arbitrary number or forge an open window.

The `marketing_consents` lookup by `lead_id` alone is therefore tenant-safe.

**Cross-tenant (FMEA-011):** conversation fetch is `.eq("id", …).eq("user_id", user.id)` → forging another tenant's `conversation_id` yields 404. Message/conversation writes use `user_id: user.id` + verified `conversation.id`; the composite FKs enforce tenant consistency. RLS is default-deny with owner-scoped SELECT, no client INSERT/UPDATE/DELETE on `messages` (append-only), and `conversations` UPDATE `WITH CHECK (user_id = auth.uid())` blocks re-parenting.

**Trigger guard:** The fix to `auth.role() IS DISTINCT FROM 'service_role'` is correct and NULL-safe — it fails **closed** for clients (blocks changes to `window_expires_at`/`last_inbound_at`/`lead_id`/`external_thread_key`/`channel`) and exempts only the service-role webhook. Client protection was never weaker than before; the fix only unblocks the webhook. `auth.role()` is schema-qualified so it resolves under `search_path=''`. Not bypassable without the service key.

**HMAC:** Verified before body use (line 113 before 120), fail-closed on missing signature/secret (line 27). Tenancy is derived from the HMAC-covered payload (`phone_number_id`/WABA id), not an out-of-band body field.

**erase_lead:** SECURITY DEFINER, `search_path=''`, validates `l.user_id = auth.uid()` and raises if not found; all deletes tenant-scoped; `GRANT EXECUTE ... TO authenticated` correct. No injection (all values flow through plpgsql variables).

**Injection:** In `whatsapp-templates`, all filters use parameterized `.eq()` — no interpolation. The webhook's `.or(\`whatsapp_phone_number_id.eq.${phoneId},whatsapp_waba_id.eq.${wabaId}\`)` (line 144) *is* raw PostgREST-filter string interpolation, but both operands are HMAC-authenticated payload fields — unreachable without `META_APP_SECRET` (a global server secret no tenant holds), and Meta only ever populates them with numeric ids. Exploitability by an untrusted client: none.
