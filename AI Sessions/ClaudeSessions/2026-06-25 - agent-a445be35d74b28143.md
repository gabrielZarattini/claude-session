### **The Bug: A Classic Race Condition**

When project `63d406fe-8357-4b90-b1ac-9ef2c0c2a975` opens, a **race** occurs between three debounced systems:

1. **Zundo's temporal debounce** (500ms) in `useCanvasStore.ts:147-152` delays publishing state snapshots
2. **useAutoSave's subscription** (3000ms debounce) in `useAutoSave.ts:8,54-65` watches `nodes`, `edges`, etc.
3. **The initialization flow** in `CanvasEditorPage.tsx:86-195` calls `initialize()` to load the graph

**The Race:** If `useAutoSave`'s effect triggers BEFORE Zustand commits the loaded nodes to the store (because of Zundo's 500ms debounce), the hook captures the initial empty arrays `nodes: []` and saves that empty state **3 seconds later** to the database, overwriting the real graph.

- The store initializes with empty defaults at `useCanvasStore.ts:62-68`
- `useAutoSave.tsx:17-22` immediately subscribes to `nodes`, `edges`, etc.
- There's NO guard to prevent writing an empty graph over a non-empty one
- There's NO hydration-complete flag to pause auto-save during load

### **Why Assets Survive**

Assets live in separate tables (`vm_canvas_executions`, `vm_canvas_assets`) and are queried independently. The empty `graph` column in `vm_canvas_projects` doesn't affect them.

1. **Add a guard** in `useSaveCanvasGraph()` to reject saving empty graphs when the DB row already has nodes
