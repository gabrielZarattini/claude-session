# firecrawl map

Discover URLs on a site. Use `--search` to find a specific page within a large site.

## When to use

- You need to find a specific subpage on a large site
- You want a list of all URLs on a site before scraping or crawling
- Step 3 in the [workflow escalation pattern](firecrawl-cli): search → scrape → **map** → crawl → interact

## Quick start

```bash
# Find a specific page on a large site
firecrawl map "<url>" --search "authentication" -o .firecrawl/filtered.txt

# Get all URLs
firecrawl map "<url>" --limit 500 --json -o .firecrawl/urls.json
```

## Options

| Option                            | Description                  |
| --------------------------------- | ---------------------------- |
| `--limit <n>`                     | Max number of URLs to return |
| `--search <query>`                | Filter URLs by search query  |
| `--sitemap <include\|skip\|only>` | Sitemap handling strategy    |
| `--include-subdomains`            | Include subdomain URLs       |
| `--json`                          | Output as JSON               |
| `-o, --output <path>`             | Output file path             |

## Tips

- **Map + scrape is a common pattern**: use `map --search` to find the right URL, then `scrape` it.
- Example: `map https://docs.example.com --search "auth"` → found `/docs/api/authentication` → `scrape` that URL.

- [firecrawl-scrape](../firecrawl-scrape/SKILL.md) — scrape the URLs you discover
- [firecrawl-crawl](../firecrawl-crawl/SKILL.md) — bulk extract instead of map + scrape

> 173	### Polling & Status Lifecycle
> 174	
> 175	The v2 client automatically polls `/requests/{request_id}/status` when `withPolling` is `true`. The API returns responses with the following structure:
> 176	
> 177	**Status Values:**
> 178	- `queued` – Request accepted and waiting for execution
> 179	- `in_progress` – Generation currently running (cannot cancel)
> 180	- `nsfw` – Content rejected by moderation, credits refunded
> 181	- `failed` – Generation errored, credits refunded
> 182	- `completed` – Generation finished and media URLs are returned
> 183	
> 184	**API Response Format:**
> 185	```json
> 186	{
> 187	  "status": "completed",
> 188	  "request_id": "d7e6c0f3-6699-4f6c-bb45-2ad7fd9158ff",
> 189	  "status_url": "https://platform.higgsfield.ai/requests/d7e6c0f3-6699-4f6c-bb45-2ad7fd9158ff/status",
> 190	  "cancel_url": "https://platform.higgsfield.ai/requests/d7e6c0f3-6699-4f6c-bb45-2ad7fd9158ff/cancel",
> 191	  "images": [{ "url": "https://image.url/example.jpg" }],
> 192	  "video": { "url": "https://video.url/example.mp4" }
> 193	}
> 194	```
> 195	
> 196	The SDK automatically converts this response into a `JobSet` with a single job, mapping `images`/`video` to `results.raw` and `results.min` for compatibility with existing code.

HIGH for Soul; for DoP HIGH that there's no such param.
- **CORS / browser:** the V2 SDK **hard-blocks browser execution** (`BrowserNotSupportedError`) — server-side only. Your Supabase edge function (Deno, server-side) is the correct place; never call from the client. HIGH.
- **Error codes (HTTP → meaning), from SDK interceptors:** `400` BadInput (also returned when cancel is not allowed), `401` Authentication (invalid credentials), `403` NotEnoughCredits, `422` Validation (FastAPI-style `detail: [{loc,msg,...}]`). HIGH (JS `client.ts:47-55`, `errors.ts`). Error body fields to parse: `detail` / `details` / `message` / `error`. HIGH (Python `error.py`). Cancel success returns `202 Accepted`. MEDIUM (official `introduction.md`).
- **NSFW path:** `status: "nsfw"` is a normal terminal state (not an HTTP error) and **refunds credits** — handle it as a soft failure, not a retry. HIGH.
