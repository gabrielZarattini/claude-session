## 7. GOTCHAS CONHECIDOS

1. **Build-time env vars:** `REACT_APP_*` são injetadas pelo Vite **em build**, não em runtime. Se você mudar `.env` depois de buildar, o frontend não reflete. Rebuild é necessário.

2. **JSX em .js:** O projeto usa `.js` para JSX (não `.jsx`). Vite está configurado para isso via `esbuild.loader: "jsx"` + `jsx: "automatic"`.

3. **Escopo CSS:** **TODO o CSS do cockpit está escopado em `.cockpit`** para não vazar pra outras partes da app (Volt/Bootstrap intactos). Classes como `.cx-line`, `.cx-panel` só funcionam dentro desse escopo.

4. **WebSocket ao vivo:** 
   - O painel usa WS para preços em tempo real via `react-use-websocket`
   - URL: `process.env.REACT_APP_WS_URL` (ex: `ws://localhost:3001`)
   - Se desconectar, reconecta a cada 3s (hardcoded em Cockpit.js:224)

5. **Polling do cockpit:** Executado a cada **60 segundos**. Se você quiser atualizar mais frequente, altere `setInterval(loadAll, 60000)` na linha 262. Cuidado: os jobs backend também têm sua cadência (ver `cockpitJob.js` no backend).

6. **Dados de paper:** 
   - Estrutura: `cp.paper.strategies[]` = array de { strategy, realizedPnl, unrealizedPnl, openPositions, fees, buys, sells, winRate, totalPnl, symbols:{...} }
   - `symbols` é um objeto onde chave=símbolo, valor={ qty, avgCost, realizedPnl, unrealizedPnl }
   - Vem de `paperService.summary()` no backend (arquivo `backend/src/utils/paperService.js`)

7. **Regime por símbolo:** Acessível via `(cp.symbols || {})[sym].gates.regime` (histerético, o que gateia as automações). Não misture com o regime instantâneo de `/analysis/regime/{sym}`.

8. **Filtro de estratégias:** Você quer só "trendstate" e "trendbreadth". No backend, isso é verificado no `paperService` — se quiser filtro front-end:
```javascript
const trendStrats = strats.filter(s => s.strategy.includes('trend') || s.strategy.includes('breadth'));
```
