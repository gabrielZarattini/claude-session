> 266	### 5.2 Invariante dura — Deploy-Target Guard (FR-LF-018)
> 267	
> 268	`assertDeployTargetAllowed(target: string)` (shared lib, chamado por `deploy-site`, `landing-bundler` publish step e `useDeployTargetGuard`):
> 269	
> 270	```
> 271	effectiveDomain(target) matches  /(^|\.)mcorch\.com$/   →  throw  { error:"deploy_target_forbidden", reason:"sso_cookie_not_httponly" }  (fail-closed)
> 272	allow  ⇔  target ∈ { *.gcrux.com (first-party), <tenant WordPress host>, <tenant BYOK Netlify/Vercel host> }
> 273	```
> 274	
> 275	Auditoria de sucesso (NFR-LF-004): **0 host `*.mcorch.com`** servindo HTML de tenant. É requisito **negativo** (FR-LF-018), não backlog. Prova material do risco anexada em cada revisão: `src/lib/sso-cookie.ts:14,:44-48`.
> 276	
> 277	### 5.3 RLS / JWT / secrets
> 278	
> 279	- **RLS default-deny** em `posthog_config`, `deploy_host_config`, flag de autonomia: policy `auth.uid() = user_id`; tenancy `user_id` (+ `project_id` em `posthog_config`); RESTRICTIVE onde aplicável.
> 280	- **JWT/ES256:** edge fns user-facing exigem JWT válido; workers/crons usam service-role (`SB_SECRET_KEY`). Edge fns com `verify_jwt=false` (se houver trigger pg_net) verificam ES256 via JWKS — nunca `atob` cego (SOP `edge-jwt-identity-verification.md`).
> 281	- **Secrets por NOME (Vault, nunca valor):** `posthog_config.personal_api_key`, `deploy_host_config.deploy_token` — cifrados at-rest (masked view + INSTEAD OF + `decrypted_*` service-role-only). Nomes de env de sistema: `SB_SECRET_KEY` (service-role). Nenhum `Deno.env.get('<SERVICE>_API_KEY')` em fluxo user-facing (API Tenancy Model — resolver per-user fail-closed 402/501).
> 282	- **Anti-SSRF universal do bundler:** `fetchPublicUrl` em TODA URL vinda do caller/DOM; validação de magic-bytes/MIME por tipo antes de embutir como `data:` URI.
> 283	
> 284	### 5.4 CISSP CBK — Software Development Security
> 285	
> 286	Defense-in-depth (agentic-vision §5.2): Survival Laws + Cyber-Sentinel + RLS default-deny + BoK Gate. Injeção XSS-safe do snippet PostHog (só `phc_`, sem interpolação de input de tenant no `<script>`). NOTICE OSS (FR-LF-019) impede violação de licença shipada em escala (FM-LF-006). Consent-gate LGPD **antes** de instrumentar (FR-LF-020); session recordings mascaram campos sensíveis.
