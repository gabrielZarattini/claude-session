- Client-supplied `bytes_sent`/`progress`/`attempts` on INSERT are cosmetic: on the first run the worker always takes the `!sessionUri` branch and forces `startAt = 0` (bridge:300-304), so a forged `bytes_sent` cannot skip byte ranges. No security impact.
- Client-controlled `playlist_id` and `snippet`/`localizations` are passed to Google, but ownership is enforced by the owner's token (Google 403s a foreign playlist); values only affect the tenant's own video. No cross-tenant effect.
- Allowing client `DELETE` of own jobs is intentional (documented, non-financial) and scoped to `auth.uid() = user_id`; a mid-flight delete only orphans a video on the owner's own channel and makes `finalize` a no-op.

The migration is consistent with the CLAUDE.md mandate that it pass `/security-review` before commit — from this review it does so cleanly.
