`openrouter-swarm/index.ts` é um **arena/benchmark N-modelos em paralelo**, não um chat. Diferenciais úteis:

- **JWT in-function + admin client separado** (`:154-180`): valida `getUser()` com o anon client, e só então cria o service-role client para ler `decrypted_user_api_keys`. Este é o **melhor template de guard** do repo.
- **Multi-provider por `byok_provider`** no body, com endpoint+chave resolvidos por switch (`:206-222`): `google`/`gemini`, `groq`, `openai`, default `openrouter`.
- **`mapModelToNativeSlug()`** (`:35-70`) — traduz slug OpenRouter→nativo. Ex.: `groq` mapeia `llama-3.3-70b*` → `llama-3.3-70b-versatile`, qualquer `llama` → `llama-3.1-8b-instant`.
- **Modelos free** (`:11-15`): `meta-llama/llama-3-8b-instruct:free`, `google/gemma-7b-it:free`, `mistralai/mistral-7b-instruct:free`.
- **Retry `:free` → pago em 429** (`:112-118`) — comentário explica que o pool `:free` do OpenRouter ignora a quota BYOK; no 429 refaz sem o sufixo. **Vale reusar no chat.**
- **`AbortController` 30s** (`:16`, `:81-82`), cap de 5 modelos (`:199`), erros capturados como objeto (nunca `throw`).
- **Tool-use: NÃO tem.** Só `{role:"user", content:prompt}`, `max_tokens:1024`, `temperature:0.7`.
- **Cobrança: NÃO tem.** Zero `deduct_mco_coins`. Erro de chave ausente → **400** (não 402), com mensagem PT-BR (`:225`).

## 4. JWT guard, CORS, erro PT-BR

### verify_jwt
`supabase/config.toml` só lista funções com `verify_jwt = false` (o cabeçalho `:3-5` explica: alvos service→service chamados com `sb_secret_`). **Funções ausentes do arquivo herdam o default `true`.** Confirmado ausentes: `canvas-execute`, `lead-score`, `aios-chat-stream`, `openrouter-swarm`, `aios-chat`. `aios-chat-gateway` está com `verify_jwt = false` (`config.toml:131-132`) porque é chamada por Database Webhook.

**Todas validam de novo in-function** — cinto e suspensório. Template canônico (`openrouter-swarm/index.ts:154-180`, idêntico em `aios-chat-stream:38-64`):

```ts
const admin = createClient(URL, (Deno.env.get("SB_SECRET_KEY") ?? Deno.env.get("SUPABASE_SERVICE_ROLE_KEY"))!);
```
Note o par de env vars com `??` — migração de chaves 2026-06; use sempre os dois.

### CORS
Bloco idêntico em ~todas (`lead-score:11-15`, `aios-chat-stream:4-9`, `openrouter-swarm:3-8`):
```ts

  "Access-Control-Allow-Origin": "*",
```

`orchestrate-content/index.ts:1-5` estende com `x-user-token, x-supabase-client-platform, …` — só necessário se o front usar `functions.invoke` de um SDK que mande esses headers.

### Erro PT-BR — o que `edgeErrorMessage` espera
`src/lib/edge.ts:8-20`, ordem de preferência **`action` → `message` → `error`**. O comentário `:11-14` é explícito: `error` costuma ser um *código de máquina* ("video_submit_failed") e vira toast ilegível se vazar sozinho.

Isso satisfaz os três níveis. **Atenção:** `edgeErrorMessage` lê `error.context` do `FunctionsHttpError` — só funciona com `supabase.functions.invoke`, **não** com `fetch` direto (ver §9).

## 6. Migrations — estilo e a questão do FK

### `vm_canvas_projects`: é **TABLE**, e FK **é viável**
Definida em `supabase/migrations/20260514040200_viralmind_canvas_studio.sql:3-21`. **TABLE**, não VIEW. Colunas: `id uuid PK`, **`user_id`** (não `owner_id`) `NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE`, `name`, `description`, `thumbnail_url`, `graph jsonb DEFAULT '{"nodes":[],"edges":[]}'`, `viewport jsonb`, `is_template`, `is_public`, `tags text[]`, `status text CHECK IN ('active','archived')`, `total_executions`, `total_credits_used`, `last_execution_at`, `created_at`, `updated_at`.

RLS (`:100`, `:105-106`): `ENABLE ROW LEVEL SECURITY` + uma política `FOR ALL TO authenticated USING (auth.uid() = user_id) WITH CHECK (auth.uid() = user_id)`. Índice `idx_vm_canvas_projects_user (user_id)` (`:93`). Trigger `updated_at` (`:126-128`). Hardening posterior: trigger `vm_canvas_projects_force_server_id` em `20260703030000_asset_owner_signing_and_ispublic_repair.sql:35-55`.

**FK composta tenant-escopada JÁ EXISTE e é o precedente exato:**
```sql

  ADD CONSTRAINT vm_canvas_projects_id_user_unique UNIQUE (id, user_id);
-- :21-25
```

Ou seja: **o âncora composto já está criado** — `spaces_node_threads` pode referenciá-lo direto, sem migration adicional.

Análogo para `spaces` (a outra superfície, coluna **`owner_id`**): `spaces_id_owner_unique` em `20260702190000_spaces_generations_ledger.sql:28`.

**Sobre "VIEWs mascaradas sem FK possível":** a suspeita não se confirma para `vm_canvas_projects`. ### 3 migrations exemplares de estilo

**(a) `supabase/migrations/20260702190000_spaces_generations_ledger.sql` — a melhor referência global.** Cabeçalho declara BoK SSOT, SOP, ordem de débito, e uma tabela D1-D8 de *divergências declaradas* do BoK (`:18-26`). Política **RESTRICTIVE no-delete** para família financeira (`:60-61`). CHECKs de domínio (`output_type`, `status` — `:38`, `:47`) e **anti-mint** (`mco_refunded <= mco_charged`, `:41`). Índices: cursor `(node_id, created_at DESC)`, `(space_id)`, e **parcial** `(status, updated_at) WHERE status IN ('pending','running')` (`:63-68`). Trigger `update_updated_at_column` (`:70-72`). `COMMENT ON TABLE` apontando a SOP (`:74-77`). RPC `SECURITY DEFINER SET search_path = ''`.

**(b) `supabase/migrations/20260710233000_space_publish_variants.sql` — o exemplar de tabela nova escrita só por edge fn.** Cabeçalho justifica *por que uma tabela nova em vez de ALTER* (`:8-11`). Tenancy explícita (`:13-15`): "NO INSERT/UPDATE policy for authenticated ⇒ default-deny writes". **Raciocínio de idempotência tenant-escopada** (`:17-22`): rejeita `node_run_id` como chave única global porque é string client-supplied → colisão cross-tenant = DoS + leak; usa `UNIQUE (user_id, source_asset_id, channel, surface)`. CHECKs nomeados (`:41-42`, `:44-46`). 4 índices, dois parciais (`:70-77`). `COMMENT` de 4 linhas.

**(c) `supabase/migrations/20260719140000_crm_suite_spine.sql` — o exemplar de família de tabelas 2026-07.** Cabeçalho `:1-5` estabelece a regra da casa: *"Toda tabela: RLS default-deny (auth.uid() = user_id) + UNIQUE (id, user_id) para FK composta tenant-escopada nos filhos"*, e explica quando usar FK simples + trigger guard (quando `ON DELETE SET NULL`, porque FK composta zeraria `user_id` — `:4-5`). ## 7. `infra_health_logs` — telemetria

Schema base em `supabase/migrations/20260425210000_mcorch_tenant_isolation.sql:90-95`: `{id, service text NOT NULL, status text NOT NULL, last_seen_at timestamptz}`. Estendido por `20260615170000_infra_health_logs_metadata.sql:13-14` com `event text` (nullable) e `metadata jsonb NOT NULL DEFAULT '{}'`.

**Não há CHECK constraint em `status`** — é allowlist por convenção, não por schema. Valores em uso: `healthy` (37×), `error` (34×), `ok` (25×), `unhealthy` (19×), `degraded` (13×).

RLS (`20260425210000:99-107`): **read por qualquer `authenticated`** (para o HUD), **write só `service_role`**. Índice `(service, last_seen_at DESC)` (`:110-111`).

**A regra de conteúdo é dura, repetida em 3 lugares:** `metadata` **NÃO pode conter PII nem segredos** — `20260615170000:10-11`, e nos call sites: `orchestrate-content/index.ts:262-263` ("Telemetry allowlist {run_id, collective_type} ONLY — NO PII (infra_health_logs is global-read)"), `_shared/llm-fallback.ts:41-42` ("Aggregate-only (fn/model/tokens, NO user_id … per-tenant attribution belongs in a scoped table"). Note que `aios-chat-gateway:220` e `openrouter-swarm:230` **violam isso** gravando `user_id` no metadata — não copie.

Dois modos de escrita:
- **Com SDK, fire-and-forget:** `admin.from("infra_health_logs").insert({...}).then(() => {}, () => {})` — `lead-score:168`, `orchestrate-content:264`.
- **Sem SDK, PostgREST direto:** `_shared/llm-fallback.ts:27-31` — útil em helper puro.

Telemetria de chave BYOK: `_shared/provider-keys.ts:99` → `keyTelemetry(r, provider)` devolve `{provider, provider_key_id, key_source}` com o comentário "NUNCA logar a chave, só o id/source".

  ```ts
    headers: { Authorization: `Bearer ${jwt}`, "Content-Type": "application/json" },
    body: JSON.stringify({ messages: msgs, system, model }),
  ```

- **Parse SSE manual** (`:234-259`): `res.body.getReader()` + `TextDecoder` + split `\n` + prefixo `"data: "` + sentinela `"[DONE]"` + `parsed?.choices?.[0]?.delta?.content`, com `catch {}` por linha para chunks partidos.
- **Erro:** `:229-232` — `if (!res.ok) { const body = await res.json(); throw new Error(body?.error ?? …) }`. **Não usa `edgeErrorMessage`** (que só funciona com `functions.invoke`, ver §4). Note que este caminho lê `body.error` — o *código de máquina* — que é justamente o que `src/lib/edge.ts:11-14` diz para não mostrar sozinho.

Lado servidor (`supabase/functions/aios-chat-stream/index.ts`): monta `formattedMessages` com o `system` primeiro (`:117-123`), pede `stream:true` (`:142`), e **reembrulha** o stream num `ReadableStream` que (a) repassa o chunk cru (`:168`) e (b) acumula o texto para faturar depois (`:171-187`). Metering roda **após `controller.close()`**, em background (`:196-205`) — `logAndDeduct` de `_shared/agent-metering.ts:12`, que usa `calc_agent_cost_mcoin` (`:69`) com fallback de pricing (`:76-89`) e **cobra 0 quando o usuário usa chave própria** (`isUserCustomKey`, `:91-92`). Resposta `Content-Type: text/event-stream` (`:215`).

Outros SSE server-side: `generate-content:158`, `generate-audio-script:167`, `generate-video-script:248`. Outros readers no front: `VideoEditorPage.tsx:427`, `ContentLibraryPage.tsx:188`, `useYouTubeUpload.ts:203`.

> **Recomendação:** `fetch` direto + `getReader()` (é o único jeito de ter SSE). **Mas** conserte o gap de erro: como `edgeErrorMessage` não alcança o `fetch`, extraia o corpo com a mesma precedência `action → message → error` no `!res.ok`, ou exporte um `edgeErrorFromResponse(res, fallback)` em `src/lib/edge.ts`. Mantenha o `AbortController` (`:214`, `:226`) — o design doc pede estado visual de "streaming" e "parar".
