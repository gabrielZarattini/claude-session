## Security Review Verdict: NO high-confidence vulnerabilities found

I read every changed file completely and traced the security-critical `pan_x/pan_y/zoom` flow end-to-end. Both fronts are clean. Details below.

### Front GRID — FFmpeg filtergraph injection: IMPOSSIBLE (the critical question)

Complete taint trace from client → ffmpeg args:

1. **Client → enqueuer** (`supabase/functions/video-render/index.ts:130-173`): `userId` comes from the JWT (`userClient.auth.getUser()`, line 44 — never the body). `resolveCell` coerces each cell's `pan_x/pan_y/zoom` via `clamp01`/`clampZoom` (`typeof v === "number" && Number.isFinite(v)` else default). A string like `"1;drawtext=..."` fails `typeof === "number"` → becomes `0.5`. The persisted composition is **rebuilt** from the resolved cells at line 173 (`composition = { mode: "split_grid", layout, cells, audio, ... }`); the client passthrough is discarded. The generic allowlist rebuild at line 210 explicitly skips split_grid (`c.mode !== "split_grid"`), so the clamped cells survive intact.
2. **Persistence** (`video-render/index.ts:261-264`): row INSERTed with the service key — the enqueuer is the only writer of `video_renders`.
3. **Worker re-clamp** (`scripts/video-bridge.ts:125-150`): `renderSplitGridRow` re-applies `clamp01`/`clampZoom` before calling `composeSplitGrid` — defense-in-depth against any forged row.
4. **Core re-clamp + format** (`scripts/hyperframes/split-screen-core.ts:137-152`): `cellFilter` clamps a **third** time. Only `panX`/`panY` reach `.toFixed(4)` (both clamped to `[0,1]` → output is `"0.0000".."1.0000"`, a pure numeric literal with no filtergraph metacharacters). `zoom` is clamped `[1,3]` then goes through `Math.round((cellW*zoom)/2)*2` → an even integer. Identity (0.5/0.5/1) emits the exact legacy string.
5. **ffmpeg invocation** (`split-screen-core.ts:30-42`, `render-core.ts:120,285,546`): `spawn(cmd, argsArray, {stdio:...})` — array args, **no `shell:true` anywhere** in the render pipeline (grep confirmed; the one `exec` hit is a JS-regex `.exec()` in an HTML template, not shell).

Answering the sub-questions: (a) values are coerced-to-number and clamped before interpolation — confirmed at all 3 layers; (b) `.toFixed(4)` on a clamped `[0,1]` number can only be a numeric literal; (c) ffmpeg is invoked with an args array, not a shell string. A string cannot reach the filter string. The committed test `scripts/hyperframes/split-grid-frame.test.ts` asserts exactly this (`pan>1→1.0000`, `pan<0→0.0000`, `NaN→0.5000`, smuggled-string→0.5, identity→byte-exact legacy).
