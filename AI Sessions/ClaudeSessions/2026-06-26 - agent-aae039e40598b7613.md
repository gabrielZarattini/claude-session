
**The catch:** `content_id` exists and references `content_library`, BUT:
1. It's written **before** publishing (when a post is scheduled), **not after** the platform assigns the POST ID.
2. `content_id` can be NULL (posts can be created without a template).
3. No index on `(platform_post_id)` for reverse lookups (platform ID → creative).
4. **No `content_variant_id` column** — creative metrics uses `content_variant_id` (= `content_library.id`), so there's terminology mismatch but they are the same.

#### **meta_posts Schema** (`20260530210000:63-85`)
```sql
CREATE TABLE IF NOT EXISTS public.meta_posts (
  id UUID PRIMARY KEY,
  user_id UUID,
  campaign_id UUID,
  platform TEXT,                          -- 'instagram' | 'facebook'
  meta_post_id TEXT NOT NULL,             -- ← POST ID
  post_url TEXT,
  caption TEXT,
  media_url TEXT,
  status TEXT,
  error_message TEXT,
  created_at TIMESTAMPTZ

```

**The catch:** `campaign_id` is present but **no `content_id` / `content_variant_id`**. A post is tied to a campaign at best, not to the individual creative.

#### **Terminology Mismatch**

- `creative_metrics` (FR-VA-009) keys on **`content_variant_id`** (= `content_library.id`)
- `scheduled_posts` has **`content_id`** (also = `content_library.id`)
- `meta_posts` has **neither** — only `campaign_id`

This means:
- For LinkedIn/Twitter posts: `scheduled_posts.platform_post_id` → `scheduled_posts.content_id` → `creative_metrics.content_variant_id` ✓ (possible but two joins)
- For Meta posts: `meta_posts.meta_post_id` → only `campaign_id` ✗ (cannot reach creative_metrics without campaign-level deduction)

### 6. THE EXACT GAPS (ACTIONABLE)

#### **Gap 1: No content reference in meta_posts**
- **Location:** `meta_posts` table (migration `20260530210000`)
- **Missing column:** `content_id UUID REFERENCES public.content_library(id) ON DELETE SET NULL`
- **Impact:** Given a Meta published post, you cannot directly query the creative that produced it.

#### **Gap 2: Reverse lookup index missing**
- **Location:** `scheduled_posts` table
- **Missing index:** `CREATE INDEX idx_scheduled_posts_platform_post_id ON scheduled_posts (platform_post_id)` (for LinkedIn/Twitter/Facebook posts via publish-social)
- **Impact:** Slow reverse lookup (platform ID → scheduled post).

#### **Gap 3: publish-social does not link platform_post_id to creative_metrics**
- **Location:** `/supabase/functions/publish-social/index.ts:241-250`
- **Current behavior:** Only updates `scheduled_posts.platform_post_id`; stops there.
- **Missing:** No row inserted into `creative_metrics` noting the publication (would seed impressions=0 if not already created by generator).
- **Impact:** Metrics attachment cannot backfill per-post analytics from the publish event.

#### **Gap 4: publish-meta does not persist content_id**
- **Location:** `/supabase/functions/publish-meta/index.ts:197-206`
- **Current behavior:** Inserts into `meta_posts` with `campaign_id` but no creative reference.
- **Missing:** Should accept and persist `content_id` parameter (like `content_node_id` exists for the mesh).
- **Impact:** No traceability from published Meta post → creative.

#### **Gap 5: auto-publish → publish-meta link is missing**
- **Location:** `/supabase/functions/auto-publish/index.ts` and publishing layer
- **Current behavior:** `auto-publish` only calls `publish-social`, not `publish-meta`.
- **Missing:** No cron path to publish via Meta for scheduled posts routed to Instagram/Facebook.
- **Impact:** Scheduled Meta posts do not publish via cron; only manual frontend publishes work.

### 7. QUERY PATH: FROM PUBLISHED POST TO CREATIVE TODAY

**For LinkedIn/Twitter (via publish-social → scheduled_posts):**
```sql
-- Forward: creative → platform post
SELECT sp.platform_post_id
FROM scheduled_posts sp
WHERE sp.content_id = $content_id
  AND sp.platform = $platform
  AND sp.status = 'published'
ORDER BY sp.published_at DESC;

-- Reverse: platform post → creative
SELECT sp.content_id, cl.title, cm.impressions
FROM scheduled_posts sp
LEFT JOIN content_library cl ON sp.content_id = cl.id
LEFT JOIN creative_metrics cm ON cl.id = cm.content_variant_id
WHERE sp.platform_post_id = $platform_post_id;
```

**For Instagram/Facebook (via publish-meta → meta_posts):**
```sql
-- Forward: creative → platform post (requires campaign detour)
SELECT mp.meta_post_id, mp.post_url
FROM meta_posts mp
WHERE mp.campaign_id = (SELECT campaign_id FROM content_library WHERE id = $content_id)
  AND mp.platform = 'instagram'
  AND mp.status = 'published'
ORDER BY mp.created_at DESC;

-- Reverse: platform post → creative (IMPOSSIBLE WITHOUT MANUAL STEPS)
SELECT mp.* FROM meta_posts mp WHERE mp.meta_post_id = $meta_post_id;
-- Result: meta_post_id, post_url, campaign_id, but NO creative link
```

### CONCLUSION

The platform **captures POST IDs correctly** but **fails to link them to creatives**. To enable per-publication analytics:

1. **Add `content_id` to `meta_posts`** — required to trace Meta posts → creative → metrics.
2. **Ensure `publish-social` and `publish-meta` receive `content_id` / `content_node_id`** — pass it through the publish request body from the UI or auto-publish.
3. **Consider a unified `published_posts` view** — or at minimum, normalize the schema (rename `content_id` to `content_variant_id` for clarity).
4. **Add the reverse index** — `idx_scheduled_posts_platform_post_id` for fast lookups.
5. **Implement the auto-publish → Meta path** — cron-based publishing to Instagram/Facebook scheduled posts.

**Data model footprint:** Three weeks to implement, ~50 LOC changes. Medium confidence on platform API stability (LinkedIn, Instagram, Facebook, Twitter all stable for the past 18 months per internal QA logs).
