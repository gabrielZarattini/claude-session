### Per sub-question

**1. Does `!key.includes('..')` + `key.startsWith(`${uid}/`)` + `realpathSync(...).startsWith(INBOX_BASE + '/')` fully prevent escape?** Yes.
- **Traversal:** `key.includes('..')` (substring, raw FS string — not URL-decoded) blocks every `../`, `....//`, etc.
- **Absolute-path injection:** `key` must start with `${row.user_id}/` (a UUID), so it can't be `/etc/...`. Even if it could, `join(INBOX_BASE, key)` treats the second arg as relative — `join('/base', '/etc/passwd') → '/base/etc/passwd'` — so an absolute key is neutralized.
- **Symlink escape (the real defense):** `realpathSync` canonicalizes ALL symlinks (including intermediate components like a symlinked `<uid>` dir), and `real.startsWith(INBOX_BASE + '/')` then rejects any canonical path landing outside the inbox root. A symlink `repurpose-inbox/<uid>/x → /etc/passwd` resolves to `/etc/passwd`, fails the prefix check → `local_source_not_found`. Correctly blocks reading `/etc/passwd`, `../.env`, etc.

**2. `INBOX_BASE + '/'` prefix robustness (sibling-dir bypass):** Correct. `resolve()` yields a canonical no-trailing-slash base; the explicit `+ '/'` means a sibling like `.../repurpose-inbox-evil/x` does NOT match `.../repurpose-inbox/`. This is the classic `startsWith` pitfall and it was handled right.
