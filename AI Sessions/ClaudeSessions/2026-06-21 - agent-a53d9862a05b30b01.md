### 2.2 Cálculo de Quantidade — beholder.js:203-296

```javascript
calcQty(orderTemplate, price, symbol) {
  // Obtém asset (USDT p/ BUY, base p/ SELL) da carteira
  asset = MEMORY[`${symbol.quote/base}:WALLET`]
  
  // Se é um número direto (ex. "0.5"), retorna como-está
  if (parseFloat(qty)) return qty
  
  // Derivação por keyword:
  
  1. MAX_WALLET (linha 222-226):
     - BUY: asset / price (× mult<1 ? 1 : mult)
     - SELL: asset (× mult>1 ? 1 : mult)
  
  2. MIN_NOTIONAL (linha 228-229):
     newQty = (symbol.minNotional / price) × (mult<1 ? 1 : mult)
     → Floor por stepSize (linha 283)
     → Se resultado < minNotional, sobe 1 stepSize [backstop -1013] (linha 292-294)
     → Essa lógica SÓ em MIN_NOTIONAL (Farm/Trend/Harvest/Paper)
  
  3. LAST_ORDER_QTY (linha 231-237):
     newQty = LAST_ORDER.quantity × mult
     → Cap na carteira se SELL
  
  4. TREND_QTY (linha 239-247):
     newQty = MEMORY[symbol:TREND_QTY] × mult
     → Lê do BRAIN (escrito em fill por updateTrendPosition)
     → Falha-fechado se vazio (throw)
     → Cap na carteira se SELL
  
  5. HARVEST_QTY (linha 249-260):
     newQty = MEMORY[symbol:HARVEST].qty × mult
     → Lê harvestPosition em MEMORY (escrito em fill por updateHarvestPosition)
     → Falha-fechado se vazio (throw)
     → Cap na carteira se SELL (protege cofre vs fee)
  
  6. FARM_QTY (linha 261-273):
     newQty = MEMORY[symbol:FARM_DCA].qty × mult
     → Lê FARM_DCA em MEMORY (escrito em fill por updateFarmPosition)
     → Falha-fechado se vazio (throw)
     → Cap na carteira se SELL (protege cofre vs fee)
  
  7. BTC_EXCESS (linha 274-281):
     newQty = (BTC_balance - 1.0) × mult [vende excessso acima do cofre]
     → Falha-fechado se balance <= 1.0
  
  return floor(newQty / stepSize) × stepSize → basePrecision
}
```
