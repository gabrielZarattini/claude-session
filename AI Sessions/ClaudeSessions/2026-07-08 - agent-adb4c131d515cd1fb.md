## Analysis

I read both the callback (mint) and session (redeem) endpoints to trace the full flow.

**The pattern is the standard OAuth authorization-code / handoff-code exchange**, with strong mitigations already in place:
- The code is 256-bit CSPRNG (`randomCode()`), stored only as a SHA-256 hash at rest (line 122–127).
- TTL is ~60s (line 126).
- Redemption (`tiktok-login-session`) is **atomically single-use**: a conditional `UPDATE ... WHERE consumed_at IS NULL AND expires_at > now() RETURNING user_id`. A second redeem matches 0 rows → replay-proof. The SPA redeems immediately on page load.

**Why the claimed exploit does not hold up:**

1. **Referer-to-third-party leak is mitigated by default browser behavior.** All modern browsers default to `Referrer-Policy: strict-origin-when-cross-origin`, which strips the path and query when sending `Referer` to any cross-origin destination. A font/image/analytics sub-resource on a different origin receives only `https://login.mcorch.com/` — never `?code=C`. Same-origin sub-resources keep the full URL, but those hit login.mcorch.com's own logs, not a third party. This is precisely why OAuth's own `code`-in-redirect-URL is industry-accepted.

2. **The remaining vectors (browser history, origin/CDN access logs) require a privileged observer to capture the code AND win a race against the victim's own immediate redeem within a 60s window against a single-use token.** That is a theoretical race requiring log/network access, not a concrete attack path driven by untrusted input — explicitly in the exclude list.

3. **The finding misreads FM-TL-02.** The SDD forbids session *tokens* (JWTs) in the URL. The handoff code is explicitly the *recommended alternative* to that — a single-use code that must be exchanged server-side (documented in the code comments at lines 4, 120: "NO session tokens in the URL"). The design complies with FM-TL-02; it does not violate it.

This is the canonical single-use handoff-code pattern with proper single-use + short-TTL + hashed-at-rest hardening. At most, moving the code to a URL fragment (`#code=`) would be marginal defense-in-depth — a hardening nicety, not a fix for a concrete vulnerability.
