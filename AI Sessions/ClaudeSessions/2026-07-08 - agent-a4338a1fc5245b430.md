## Verification complete

I read all four files in the flow: `tiktok-login-init/index.ts`, `tiktok-login-callback/index.ts`, `tiktok-login-session/index.ts`, and the SPA `src/pages/TikTokLoginCallback.tsx`.

**Confirmed the core claim.** There is genuinely no binding between the browser that starts the flow and the one that finishes it:

- `tiktok-login-init:50` signs a stateless HMAC `{intent, nonce, ts}` and returns the authorize URL as JSON — **no `Set-Cookie`**, so nothing is planted in the initiating browser.
- `tiktok-login-callback:121-131` mints a single-use handoff code and 302s it as a URL query param (`/auth/tiktok/callback?code=C`). The code row (`tiktok_login_codes`) stores only `code_hash`, `user_id`, `expires_at` — **no browser/session correlation**.
- `tiktok-login-session:53-95` atomically consumes the code and mints a full Supabase session for whatever `user_id` the code maps to. It requires only possession of the code — a pure bearer token.
- `TikTokLoginCallback.tsx:18-40` **auto-redeems on page load** and immediately calls `setSession()` with zero correlation to who initiated the flow.

So the attack path holds: an attacker completes TikTok OAuth with their own account, captures `?code=C`, and induces the victim to load that login.mcorch.com URL within the 60s TTL → the victim's browser silently redeems it and is logged into the attacker's account (classic login CSRF / session fixation). Subsequent BYOK keys, billing, connected socials the victim configures live in the attacker's account.

**Two honest caveats** (don't negate it, but bound severity):
- The redeemer must load the actual SPA page (top-level navigation), so a blind `<img>` tag does *not* fire it — the finding overstates that. It requires a link click, `window.open`, or top-level redirect from an attacker page. Meta-refresh / redirect still works.
- The 60s window demands tight timing, defeatable via a real-time push channel but adding friction.

This is real, in-scope (session-minting auth code), and exploitable with untrusted input. Not a false positive.

**One-line fix:** At `tiktok-login-init`, set an HttpOnly, `SameSite=Lax` cookie with a random binding value and embed its hash in the signed `state`; at `tiktok-login-callback` store that binding on the `tiktok_login_codes` row, and require the same cookie at `tiktok-login-session` redemption — so the handoff code is only redeemable by the browser that initiated the flow.
