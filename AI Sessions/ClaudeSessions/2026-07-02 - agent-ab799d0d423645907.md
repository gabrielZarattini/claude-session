## VERDICT: FINDINGS

The core money invariants hold — I could not find a mint, double-charge, double-refund, cross-tenant charge, or daily-cap bypass. The two migration RPCs are well-constructed (signature-exact grants, clamped refund + CHECK backstop, claim-guarded finalize, composite tenant FK). The surviving findings are **charge-without-value / reconciliation robustness gaps around finalize-RPC failure**, the most serious being that the documented recovery sweep does not exist.

### What I verified as SAFE (no findings)

- **MINT** — `begin_space_generation` rejects `p_amount < 0` (`:103-105`); `deduct_mco_coins` independently guards `p_amount <= 0` (freeze migration `:104-107`). Refund is triple-guarded: `LEAST(GREATEST(COALESCE(p_refund,0),0), mco_charged)` (`:163`), the column CHECK `mco_refunded <= mco_charged` (`:41`), and `add_mco_coins` rejecting non-positive (`:23`). A `mco_charged=0` no-op run cannot yield a positive refund. **REVOKE/GRANT trailer is signature-exact and complete** — both RPCs `REVOKE ALL … FROM PUBLIC, anon, authenticated` + `GRANT … TO service_role` only (`:187-195`), matching the arg lists byte-for-byte and the `add_mco_coins` service-role-only precedent.
- **DOUBLE-CHARGE** — `ON CONFLICT (node_run_id) DO NOTHING RETURNING id` (`:109-110`); duplicate → `v_id IS NULL` → returns prior state with zero debit (`:112-116`). Two concurrent begins with the same `node_run_id` serialize on the unique index (one debits, the other blocks then no-ops). The edge branch `return await executeSpacesNode(...)` (`index.ts:241-242`) is exclusive — it never falls through to the legacy deduct-after-success paths.
- **DOUBLE-REFUND** — finalize claims via `WHERE … status IN ('pending','running')` (`:164-165`); under READ COMMITTED the second concurrent finalizer re-evaluates the now-terminal row (EvalPlanQual), matches 0 rows, returns `{finalized:false}` (`:168-170`). First finalizer wins.
- **CROSS-TENANT** — `begin` takes `p_owner_id` = `user.id` from the JWT; the composite FK `(space_id, owner_id) → spaces(id, owner_id)` (`:49-50`, anchored by `UNIQUE(id, owner_id)` `:28`) makes it schema-impossible to attach a generation to another tenant's space; the edge pre-check 404s on foreign/absent space (`index.ts:731-736`). `finalize` derives `owner_id` **from the claimed row**, never from caller input (`:166`) — refunds always land on the true owner. RLS is SELECT-own + RESTRICTIVE no-delete; no write policy for `authenticated`.

### FINDINGS

**[MEDIUM] Finalize(error) failure is swallowed → charge retained, false "refunded" reported, and the documented recovery sweep does not exist.**
`index.ts:791-811` (provider fail) and `index.ts:865-876` (asset-persist fail). On the provider-fail path, `finErr` is only `console.error`'d (`:799`) and the response unconditionally reports `refunded: fin?.refunded ?? creditCost` (`:809`). On the asset-persist path, the finalize call captures **no** error at all (`:867-870`) yet returns `refunded: creditCost` (`:875`). If the `finalize_space_generation` RPC fails transiently, the `'running'` row and the debit both persist, but the user is told the money was estornado (a Law 1 materiality misreport). The migration and SOP name `scripts/self-heal-spaces.sh` as the >30-min stuck-run recovery (`docs/processes/spaces-graph-execution.md:72`, `docs/bok/spaces-evolution/08-quality-metrics.md:88`) — **but that file does not exist** (`test -f` → DOES NOT EXIST; no cron references it). So in Fase 1b a finalize failure is a permanent, silent charge-without-value with no safety net. Not attacker-triggerable (requires a DB blip), hence MEDIUM.
*Fix:* (a) ship `self-heal-spaces.sh` in this slice (or gate the merge on it); (b) only claim `refunded` when `finErr` is null — otherwise return `refund_pending:true` so the response matches the ledger truth; (c) optionally retry finalize once before returning.

**[LOW] Finalize(done) failure → stuck 'running' row after value delivered → future sweep will false-refund a delivered generation (value-without-charge).**
`index.ts:816-822` (magic_prompt) and `:902-909` (image) call `finalize(done)` with no error check, *after* the 200 with `output_url`/`enhanced_prompt` is already committed and the asset registered. If that RPC blips, the row stays `'running'`. The sweep, as specified ("running >30min → error + refund, NEVER re-charge"), cannot distinguish delivered-but-finalize-failed from genuinely-stuck, so it will refund a generation the user already received. Latent today (sweep unbuilt), activates when Finding 1's fix ships.
*Fix:* the sweep must only refund rows with `asset_id IS NULL AND result IS NULL` (no delivered value), or persist a delivered marker before returning 200, or retry finalize(done).

**[LOW] Frozen-account error mapping leaks the internal quarantine message and returns 500.**
When the owner is frozen, `deduct_mco_coins` raises `'Conta congelada por quarentena de segurança'` (ERRCODE 42501), rolling back `begin`. The edge only special-cases the substring `"Saldo mcoCoins insuficiente"` → 402; everything else → **500 with the raw RPC message echoed to the client** (`index.ts:744-751`). The account is correctly blocked (no debit), but the status is wrong and an internal security message leaks.
*Fix:* map `42501`/"Conta congelada" to 403 with a generic PT-BR message; never echo raw RPC exception text to clients.

**[INFO] Idempotency-key collision cross-tenant existence disclosure.**
`begin_space_generation`'s duplicate branch selects the conflicting row by `node_run_id` alone (`:114`) and the edge returns its `generation_id` + `status` (`index.ts:766-772`). If user A submitted a `node_run_id` already owned by B, A would receive B's generation uuid + status. Not practically exploitable — A must guess B's 128-bit random uuid — and no money moves and no output content leaks. Optional hardening: filter the duplicate lookup by `owner_id = p_owner_id` and treat an owner mismatch as a conflict error rather than returning the foreign row.

---

**Bottom line:** No exploitable mint or cross-tenant money movement survives review — the ledger RPCs are sound. The blocking concern before shipping is **Finding 1**: the finalize-failure recovery path (`self-heal-spaces.sh`) is referenced everywhere but not implemented, so any finalize-RPC blip becomes an unrecoverable charge-without-value that the API falsely reports as refunded. I recommend not sealing this as delivered until the sweep exists (or the response stops claiming a refund it didn't verify committed).
