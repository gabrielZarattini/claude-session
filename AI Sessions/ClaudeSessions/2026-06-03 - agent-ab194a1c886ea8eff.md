## Context (why)
An E2E found that ~74% of FILLED orders (all MARKET) have `net` and `avgPrice` NULL → P&L, cost-basis and the Wallet "AVG PRICE" column are broken. Root cause: MARKET orders return from Binance already `status:FILLED`, but the insert paths (`beholder.placeOrder`, `ordersController.placeOrder`) never compute net/avgPrice/commission — they delegate to the `executionReport` userData stream, which is intermittent, so most market fills end up with NULL financials.

## The fix
1. New pure helper `ordersRepository.calcFillFinancials(result, symbol)`: from the exchange order response (`executedQty`, `cummulativeQuoteQty`, `fills[]`) returns `{avgPrice, net, commission, isMaker}` when `executedQty>0`, else `{}`. Net = cummulativeQuoteQty, minus commission only when commission is in the QUOTE asset (mirrors the existing `processExecutionData` logic in app-em.js: `isQuoteCommission ? quoteAmount - commission : quoteAmount`).
2. Both insert paths spread `...calcFillFinancials(result, symbol)` into the `insertOrder({...})` call (after `status`), so market fills persist net/avgPrice/commission immediately. Non-executed responses (LIMIT NEW, EXPIRED qty=0) get `{}` → unchanged behavior.
3. Frontend (unrelated, small): OCO order-template now locks Side=SELL (`SelectSide` gets a `disabled` prop; `OrderTemplateModal.onInputChange` forces `side='SELL'` when type becomes OCO) — backend rejects OCO BUY, so this prevents a runtime error.

Unit check already run (synthetic fills): BUY w/ BTC commission → net=full quote (commission NOT deducted, correct, it's base-denominated); SELL w/ USDT commission → net = quote − commission; EXPIRED qty=0 → {}.
