### 2. **GERAÇÃO DE GRIDS: `generateGrids()` E COMO NÍVEIS SÃO CALCULADOS**

**Localização:**
- `/home/gcrux-tradeux/tradeux/backend/src/beholder.js:532-634`

**Lógica central (CÓDIGO-CHAVE):**

```javascript
async function generateGrids(automation, levels, quantity, transaction) {
    await gridsRepository.deleteGrids(automation.id, transaction);
    
    const symbol = await getSymbol(automation.symbol);
    const tickSize = parseFloat(symbol.tickSize);
    
    // EXTRAI lowerLimit E upperLimit DOS CONDITIONS DA AUTOMAÇÃO
    const conditionSplit = automation.conditions.split(' && ');
    const lowerLimit = parseFloat(conditionSplit[0].split('>')[1]);
    const upperLimit = parseFloat(conditionSplit[1].split('<')[1]);
    levels = parseInt(levels);
    
    // CALCULA ESPAÇAMENTO
    const priceLevel = (upperLimit - lowerLimit) / levels;
    const grids = [];
```

**Como funciona:**

1. **Parse dos limites:** A automation.conditions é uma string como:
   ```
   "MEMORY['ETHUSDT:BOOK'].current.bestAsk > 1900 && MEMORY['ETHUSDT:BOOK'].current.bestAsk < 2200"
   ```
   Daí extrai `lowerLimit = 1900` e `upperLimit = 2200`

2. **Espaçamento:** `priceLevel = (2200 - 1900) / levels = 300 / levels`
   - Se `levels = 10`, então `priceLevel = 30` USDT entre cada grid

3. **Geração de grids:** Para cada `i` de 1 até `levels`:
   ```javascript
   for (let i = 1; i <= levels; i++) {
       const priceFactor = Math.floor((lowerLimit + (priceLevel * i)) / tickSize);
       const targetPrice = priceFactor * tickSize;
       
       // Se preço ALVO < preço atual → COMPRA (grid de BUY)
       if (targetPrice < currentPrice) {
           const previousLevel = targetPrice - priceLevel;
           grids.push({
               automationId: automation.id,
               conditions: `MEMORY['${automation.symbol}:BOOK'].current.bestAsk<${targetPriceStr} && 
                           MEMORY['${automation.symbol}:BOOK'].previous.bestAsk>=${targetPriceStr} && 
                           MEMORY['${automation.symbol}:BOOK'].current.bestAsk>${previousLevelStr}`,
               orderTemplateId: buyOrderTemplate.id
           })
       }
       // Se preço ALVO > preço atual → VENDE (grid de SELL)
       else {
           const nextLevel = targetPrice + priceLevel;
           grids.push({
               automationId: automation.id,
               conditions: `MEMORY['${automation.symbol}:BOOK'].current.bestBid>${targetPriceStr} && 
                           MEMORY['${automation.symbol}:BOOK'].previous.bestBid<=${targetPriceStr} && 
                           MEMORY['${automation.symbol}:BOOK'].current.bestBid<${nextLevelStr}`,
               orderTemplateId: sellOrderTemplate.id
           })
       }
   }
   
   // REMOVE O GRID MAIS PRÓXIMO DO PREÇO ATUAL (para evitar ordens imediatas)
   const nearestGrid = differences.findIndex(d => d === Math.min(...differences));
   grids.splice(nearestGrid, 1);
   
   return gridsRepository.insertGrids(grids, transaction);
   ```

4. **OrderTemplates criados:** `generateGrids()` cria automaticamente 2 templates por grid:
   - `<automation.name> BUY` (MARKET, BUY, qty=quantity)
   - `<automation.name> SELL` (MARKET, SELL, qty=quantity)
   - Esses templates são **reutilizados** pelos grids (cada grid aponta a um deles via `orderTemplateId`)

### 3. **COMO UM GRID COLOCA E GERENCIA ORDENS: O FLUXO COMPLETO**

**Entrada no sistema:**
- `/home/gcrux-tradeux/tradeux/backend/src/beholder.js:493-530` — função `gridEval()`

**Fluxo passo a passo:**

1. **Condition check:** A cada tick de mercado (BOOK update), o `beholder.updateMemory()` em `app-em.js:44` gateia a avaliação de automações. Quando a automation é tipo GRID, chama `gridEval()`

2. **Avalia cada grid da automação:**
   ```javascript
   async function gridEval(settings, automation) {
       automation.grids = automation.grids.sort((a, b) => a.id - b.id);
       
       for (let i = 0; i < automation.grids.length; i++) {
           const grid = automation.grids[i];
           
           // AVALIA A CONDITION DO GRID (ex: preço caiu e passou por um nível)
           if (!Function("MEMORY", "return " + grid.conditions)(MEMORY)) 
               continue;
   ```

3. **Condição casou → coloca ordem:**
   ```javascript
           // Pega o orderTemplate associado ao grid que casou
           automation.actions[0].orderTemplateId = grid.orderTemplateId;
           
           // Busca o book (necessário para calcular preço/qty)
           const book = MEMORY[`${automation.symbol}:BOOK`];
           if (!book) return { type: 'error', text: ... };
           
           // COLOCA A ORDEM via placeOrder()
           const result = await placeOrder(settings, automation, automation.actions[0]);
   ```

4. **Após a ordem colocar:**
   ```javascript
           // REGENERA os grids: deleta todos e cria novos com +1 level
           const transaction = await db.transaction();
           try {
               const orderTemplate = await orderTemplatesRepository.getOrderTemplate(grid.orderTemplateId);
               await generateGrids(
                   automation, 
                   automation.grids.length + 1,  // +1 level a cada ordem
                   orderTemplate.quantity,        // qty constante
                   transaction
               );
               await transaction.commit();
           } catch (err) {
               await transaction.rollback();
               return { type: 'error', text: ... };
           }
   ```

**CRÍTICO — O que NÃO está implementado:**

- **Ordens RESTING:** Os grids geram um `grid.conditions` que é **apenas textual** — **não criamuma ordem RESTING na corretora**. Cada grid é um padrão de condição avaliado em memória.
- **Rebuy/Resell:** Não há lógica hardcoded de "refill". Quando uma ordem executa, apenas **regenera-se os níveis** com `generateGrids()`. A rejeição de uma leg anterior *não é automática* — uma nova ordre de BUY será colocada quando o preço cair novamente.
- **No-loss nativo:** A documentação (`STRATEGY-farm-funnel.md:65-66`) diz que o no-loss **"reusa o grid nativo"** + `MEMORY['<sym>:LAST_ORDER']` para custo — mas **essa lógica de "só vender com lucro" NÃO está codificada em `generateGrids()` ou `gridEval()`**. É uma **responsabilidade da ordem template** (verificar se há validação no `calcPrice()` ou `placeOrder()` — há refs a `avgPrice`, `net`, `commission` em `calcFillFinancials()` mas **não há gate de "lucro mínimo"** em nenhum lugar do código atual).

### 6. **LÓGICA DE "NO-LOSS" LIGADA A GRID OU MEMORY['<sym>:LAST_ORDER']**

**Status: PARCIALMENTE IMPLEMENTADO (design documentado, implementação INCOMPLETA)**

**Documentação (intencional):**
- `/home/gcrux-tradeux/tradeux/docs/STRATEGY-farm-funnel.md:65-66`
  - "No-loss (regra do dono): vender só quando `preço × (1−fee) ≥ custo × (1+lucro_alvo)`. Reusa o **grid nativo do Beholder** (`gridEval`/`generateGrids`) + `MEMORY['<sym>:LAST_ORDER']` pro custo."

**Referências a LAST_ORDER no código:**
- `/home/gcrux-tradeux/tradeux/backend/src/beholder.js:228-235`
  - `calcQty()` suporta `LAST_ORDER_QTY` como quantity (multiplica qty da última ordem)
  - Acessa `MEMORY[`${orderTemplate.symbol}:LAST_ORDER`]`
- `/home/gcrux-tradeux/tradeux/backend/src/app-em.js:227, 271, 523`
  - Escreve `LAST_ORDER` na memória quando uma ordem executa:
    ```javascript
    await beholder.updateMemory(order.symbol, indexKeys.LAST_ORDER, null, orderCopy);
    ```

**O que NÃO está implementado:**
- **Gate de lucro:** Não há validação em `gridEval()` ou `placeOrder()` que diga "só vender se `currentPrice × (1 − fee) ≥ lastOrderPrice × (1 + lucro_alvo)`"
- **Custo-base:** `LAST_ORDER` é rastreado, mas o **custo médio** (avg fill price) não é persistido nem comparado nas conditions dos grids
- **No-loss como automação:** O conceito está no design (`STRATEGY-farm-funnel.md`) mas a implementação esperada (Fase 2) ainda não está ativa no código

**Conclusão:** A infraestrutura (`LAST_ORDER` em memória, grid conditions dinâmicas) existe, mas a **lógica de "só vender com lucro" não está hardcoded**. Seria necessário:
1. Persistir `avgPrice` das ordens executadas (já coleta em `calcFillFinancials()`)
2. Modificar `generateGrids()` ou `gridEval()` para comparar `currentPrice × (1 − fee) ≥ avgPrice × (1 + lucroAlvo)`
3. Rejeitar ordens de SELL que não atendem o critério
