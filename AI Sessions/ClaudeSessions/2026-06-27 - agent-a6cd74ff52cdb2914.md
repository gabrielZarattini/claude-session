# firecrawl scrape

Scrape one or more URLs. Returns clean, LLM-optimized markdown. Multiple URLs are scraped concurrently.

## When to use

- You have a specific URL and want its content
- The page is static or JS-rendered (SPA)
- Step 2 in the [workflow escalation pattern](firecrawl-cli): search → **scrape** → map → crawl → interact

## Quick start

```bash
# Basic markdown extraction
firecrawl scrape "<url>" -o .firecrawl/page.md

# Main content only, no nav/footer
firecrawl scrape "<url>" --only-main-content -o .firecrawl/page.md

# Wait for JS to render, then scrape
firecrawl scrape "<url>" --wait-for 3000 -o .firecrawl/page.md

# Multiple URLs (each saved to .firecrawl/)
firecrawl scrape https://example.com https://example.com/blog https://example.com/docs

# Get markdown and links together
firecrawl scrape "<url>" --format markdown,links -o .firecrawl/page.json

# Ask a question about the page
firecrawl scrape "https://example.com/pricing" --query "What is the enterprise plan price?"
```

## Options

| Option                   | Description                                                      |
| ------------------------ | ---------------------------------------------------------------- |
| `-f, --format <formats>` | Output formats: markdown, html, rawHtml, links, screenshot, json |
| `-Q, --query <prompt>`   | Ask a question about the page content (5 credits)                |
| `-H`                     | Include HTTP headers in output                                   |
| `--only-main-content`    | Strip nav, footer, sidebar — main content only                   |
| `--wait-for <ms>`        | Wait for JS rendering before scraping                            |
| `--include-tags <tags>`  | Only include these HTML tags                                     |
| `--exclude-tags <tags>`  | Exclude these HTML tags                                          |
| `-o, --output <path>`    | Output file path                                                 |

## Tips

- **Prefer plain scrape over `--query`.** Scrape to a file, then use `grep`, `head`, or read the markdown directly — you can search and reason over the full content yourself. Use `--query` only when you want a single targeted answer without saving the page (costs 5 extra credits).
- **Try scrape before interact.** Scrape handles static pages and JS-rendered SPAs. Only escalate to `interact` when you need interaction (clicks, form fills, pagination).
- Multiple URLs are scraped concurrently — check `firecrawl --status` for your concurrency limit.
- Single format outputs raw content. Multiple formats (e.g., `--format markdown,links`) output JSON.
- Always quote URLs — shell interprets `?` and `&` as special characters.
- Naming convention: `.firecrawl/{site}-{path}.md`

- [firecrawl-interact](../firecrawl-interact/SKILL.md) — when scrape can't get the content, use `interact` to click, fill forms, etc.

> 583	## Sandbox limitations
> 584	
> 585	Use Sandbox only for your own ad account, associated entities, Pins and boards.
> 586	
> 587	Also, note that entities in your Sandbox environment are separate from entities in your production environment. For example, you cannot use a Pin in Sandbox to create an ad in production.
> 588	
> 589	You cannot do the following in Sandbox, although some of these capabilities may be supported in the future:
> 590	
> 591	- Create video Pins.
> 592	
> 593	- Create or manage shopping ads.
> 594	
> 595	- Test business access.
> 596	
> 597	- Simulate the ads auction, feed status checks, conversion upload, or bulk editing.
> 598	
> 599	
> 600	## Start using Sandbox
> 601	
> 602	### Step 1. Set up your app
> 603	
> 604	If you have not yet set up your app to work with Pinterest, follow the instructions on the [app setup page](https://developers.pinterest.com/docs/getting-started/connect-app/) to connect and configure an app.
> 605	
> 606	### Step 2. Generate a Sandbox access token
> 607	
> 608	To use Sandbox, you need a specific token, which is tied to your Pinterest user account. You cannot use the Sandbox token in your production environment, nor can you use a production token for Sandbox.
> 609	
> 610	#### Generate a token on your app management page
> 611	
> 612	You can generate a Sandbox token quickly and easily on your app management page. The token lasts 30 days, after which, you could generate a new one if necessary.
> 613	
> 614	1. Go to the [My Apps page](https://developers.pinterest.com/apps/).
> 615	
> 616	2. Select **Manage** for the app you want to give Sandbox access.
> 617	
> 618	3. In the **Configure** tab, scroll down to the **Generate Access Token** section.
> 619	
> 620	4. Select **Sandbox** as the environment.
> 621	
> 622	5. Click **Generate token**.
> 623	
> 624	6. Copy the generated token, to use in Sandbox API calls.
> 625	
> 626	
> 627	#### Generate a token using the OAuth flow
> 628	
> 629	You can also generate a Sandbox token using the [OAuth flow](https://developers.pinterest.com/docs/getting-started/set-up-authentication-and-authorization/#generate-an-access-token). This could be useful if you want to continuously refresh the token for long-term testing in Sandbox. Also, with an OAuth token, you can select specific scopes.
> 630	
> 631	When calling
> 632	[POST\\
> 633	\\
> 634	Generate OAuth access token](https://developers.pinterest.com/docs/developer-tools/sandbox/)
> 635	you would insert
> 636	
> 637	`-sandbox`
> 638	
> 639	in the URL request path as in the following example:
> 640	
> 641	`curl -X POST https://api-sandbox.pinterest.com/v5/oauth/token \`
> 642	
> 643	See the full guide for [generating an access token using the OAuth flow](https://developers.pinterest.com/docs/getting-started/set-up-authentication-and-authorization/#generate-an-access-token).
> 644
