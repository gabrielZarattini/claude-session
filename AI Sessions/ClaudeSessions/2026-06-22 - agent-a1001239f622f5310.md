### Racional (respondendo aos 5 pontos)

1. **Função pura é a abordagem certa.** O bug do `6b9b97b` foi exatamente "endpoint tem o campo ≠ tool encaminha o campo" — uma falha de **transformação de payload**, não de I/O. Extrair a transformação pura (`buildCockpitOut`) e testá-la diretamente ataca a causa raiz sem o custo/flakiness de subir stdio+backend só pra inspecionar a forma do `out`. O acoplamento é são e unidirecional (`index.js` → `cockpitOut.js`, nenhum import reverso, `cockpitOut` não importa nada). Bônus: o handler ficou de ~22 linhas para 1 expressão legível.

2. **`&&` no `npm test` está correto.** Verificado ao vivo: roda os dois e `EXIT=0`; o `&&` propaga falha (short-circuit + exit code do primeiro que falhar — e o `cockpit-out.mjs` faz `process.exit(failed?1:0)`). Encadear é melhor que um step de CI separado aqui porque o job de integração já invoca `npm test` do mcp — um step novo no `ci.yml` duplicaria o `working-directory`/setup sem ganho. O rename do step (`Self-tests do MCP …`) reflete a cobertura nova com honestidade.

3. **`.mjs` em `tradeux-mcp/test/` é o lugar certo.** O pacote mcp é `type:module`; o backend é CJS. Forçar o teste no runner de sim do backend (`scripts/sim`, CJS) criaria o mismatch ESM/CJS que a própria pergunta levanta, e pioraria a coesão (testaria código do mcp a partir do backend). Fica junto do `place-order-vault-guard.mjs`, mesmo estilo, mesmo runner (`node`). Coerente.

4. **Convenções OK.** pt-BR nos comentários/asserts, naming consistente (`buildCockpitOut`, `cockpit-out.mjs` espelha `cockpitOut.js`). O comentário documenta bem o **porquê** — cita o commit `6b9b97b`, explica que "verificado ao vivo testou o ENDPOINT, não o TOOL" (a lição certa) e o detalhe do `|| null` (falsy-mas-válido preservado), que o teste (2) cobre explicitamente. Documentação de regressão exemplar.

5. **Dívida residual aceitável.** O teste é unit puro e não exercita o tool via stdio ponta-a-ponta — mas o `place-order-vault-guard.mjs` já cobre o caminho stdio do servidor, e o `agent --check` no CI sobe o MCP e lista as tools.
