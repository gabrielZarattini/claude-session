# THE COLLECTIVE EFFICIENCY LEDGER VIEW (canonical SQL — para 06-data-model + 05-sdd)
CREATE VIEW public.collective_efficiency_ledger WITH (security_invoker = on) AS
  SELECT pr.id AS run_id, 'orchestrate-content'::text AS collective_type, pr.user_id,
         COALESCE(jsonb_array_length(pr.steps),0) AS n_units, pr.mco_cost AS mco_projected,
         pr.mco_cost AS mco_actual, pr.status AS result_status,
         (pr.status IN ('done')) AS succeeded,
         (EXTRACT(EPOCH FROM (pr.completed_at - pr.started_at))*1000)::bigint AS wall_clock_ms, pr.started_at
  FROM public.pipeline_runs pr
  UNION ALL
  SELECT ac.id, 'autopilot-cycle'::text, ac.user_id, ac.planned_units, ac.spend_mco,
         (ac.spend_mco - ac.refunded_mco), ac.status, (ac.status IN ('completed')),
         (EXTRACT(EPOCH FROM (ac.completed_at - ac.started_at))*1000)::bigint, ac.started_at
  FROM public.autopilot_cycles ac;
Cross-tenant rollup = RPC collective_efficiency_rollup() SECURITY DEFINER, search_path='', GRANT service_role only — agrega AVG(mco_actual), AVG(wall_clock_ms), retry-rate por collective_type, ALL tenants.

> 200	### 4.5 Async Job & Partial-Delivery Refund Contract (sela FM-VM-07 / BR-VM-003 / BAC-VM-007)
> 201	
> 202	> Regra definida AQUI, antes de qualquer código — exigência do BRD ("regra selada no FRD antes da Fatia 3").
> 203	
> 204	1. **Débito integral na entrada:** `deepsearch.run` debita a classe inteira (3 mco) via `deduct_mco_coins` antes do enqueue. Saldo insuficiente → 402, job não nasce.
> 205	2. **Unidades entregáveis:** todo job declara `planned_units` (páginas/queries) no aceite; o estado terminal reporta `delivered_units`.
> 206	3. **Falha total (`delivered_units = 0`):** estado `failed`; `refundMco` credita o valor integral; delta líquido de `mco_balance` = 0 (prova por `SELECT` before/after).
> 207	4. **Entrega parcial (`0 < delivered < planned`):** estado `partial`; cobrança retida = `max(1, floor(class_mco × delivered_units / planned_units))`; refund = `class_mco − retida`, executado via `refundMco` ANTES de o job ir a terminal. Arredondamento sempre A FAVOR do tenant (floor na cobrança).
> 208	5. **Transparência:** resultado parcial entregue com `partial: true` + `failed_units[]` + `refunded_mco` explícito no payload do poll.
> 209	6. **Idempotência:** refund por job é executado no máximo uma vez (guard por `job_id` no contexto do RPC); retries de poll nunca re-disparam refund.
