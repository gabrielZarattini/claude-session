> 58	**3 fns vs 2 (OTD-TL-005):** a terceira fn (`tiktok-login-session`) isola o resgate do código single-use do fluxo de redirect, permitindo rate-limit/Origin-guard próprios e mantendo o `callback` livre de resposta com corpo-de-sessão. Dobrar no callback é possível, mas quebra o mandato "zero token na URL" (o callback é atingido por redirect de browser). Rec: **3 fns**.

> 155	## 4. API Contract Definitions
> 156	
> 157	> Ordem por request no `callback`: **Origin/self-guard → `verifyState` fail-closed → exchange server-side → find-or-create → mint → code hand-off**. Nenhum path debita mcoCoins. `verify_jwt=false` nas 3 fns; a proteção é `state` HMAC + Origin (§5.1), não JWT.
> 158	
> 159	### 4.1 Endpoints
> 160	
> 161	| Endpoint | Method | Auth | Contract |
> 162	|----------|--------|------|----------|
> 163	| `/functions/v1/tiktok-login-init` | POST | público (`verify_jwt=false`) | `{return_to?}` → `{url}` (authorize URL c/ `state` assinado). Erros: 400 `invalid_request` · 500 `internal_error` |
> 164	| `/functions/v1/tiktok-login-callback` | GET | público (`verify_jwt=false`) + `verifyState` | `?code&state` → **302** `/auth/tiktok/callback?code=<one_time>` (sucesso) \| **302** `/auth?tiktok_error=<reason>` (falha) |
> 165	| `/functions/v1/tiktok-login-session` | POST | público (`verify_jwt=false`) + Origin-guard | `{code}` → `{access_token,refresh_token}` (1×). Erros: 400 · 403 `origin_invalid` · 404 `code_not_found` · 410 `code_expired_or_consumed` |
> 166	
> 167	### 4.2 `tiktok-login-init` (FR-TL-002)
> 168	
> 169	```typescript
> 170	// state assina intent+nonce (NÃO userId — login não tem auth.uid()); difere de social-auth-init:63-64
> 171	const state = await signState(
> 172	  { intent: 'login', nonce: crypto.randomUUID(), return_to: safeReturnTo() ?? null, ts: Date.now() },
> 173	  Deno.env.get('SB_SECRET_KEY')!,

> 175	const url = `https://www.tiktok.com/v2/auth/authorize/`
> 176	  + `?client_key=${encodeURIComponent(Deno.env.get('TIKTOK_CLIENT_KEY')!)}`
> 177	  + `&response_type=code`

> 182	```

> 184	### 4.3 `tiktok-login-callback` (FR-TL-003/004/006)
> 185	
> 186	```typescript
> 187	// 1. verifyState fail-closed (oauth-state.ts:43-61) — intent==='login' exigido
> 188	const parsed = await verifyState<{ intent: string; return_to: string | null }>(
> 189	  state, Deno.env.get('SB_SECRET_KEY')!, { maxAgeMs: 600_000 })
> 190	if (!parsed || parsed.intent !== 'login') return redirect('/auth?tiktok_error=state_expired')

> 192	// 2. Exchange server-side (form-encoded — provado social-auth-callback:184-194)
> 193	const tokenRes = await fetch('https://open.tiktokapis.com/v2/oauth/token/', {
> 194	  method: 'POST', headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
> 195	  body: new URLSearchParams({
> 196	    client_key: Deno.env.get('TIKTOK_CLIENT_KEY')!,

> 198	    code, grant_type: 'authorization_code', redirect_uri: REGISTERED_LOGIN_CALLBACK }),
> 199	})
> 200	const { open_id } = await tokenRes.json()   // descarta access_token/refresh_token (identity-only)
> 201	
> 202	// 3. find-or-create tiktok_identities → 4. generateLink→verifyOtp (mint) → 5. INSERT code_hash (TTL 60s)

> 256	// tiktok-login-callback — a ÚNICA prova de que este redirect pertence a um init legítimo é o state assinado.

> 275	### 5.5 The NO-AUTO-LINK-BY-EMAIL Rule (anti cross-tenant grafting)
> 276	
> 277	> **Regra de segurança de produto (hard rule — FM-TL-03 · RISK-TL-003 · BR-TL-004 · MR-TL-004):**
> 278	
> 279	1. A identidade é chaveada **ESTRITAMENTE por `open_id`** app-scoped. Um `open_id` novo cria uma conta **nova e isolada** — nunca resolve para uma conta email/Google pré-existente.
> 280	2. É **PROIBIDO** no design: buscar `auth.users` por email para "casar" um login TikTok com uma conta existente; aceitar um `userId`/email do `state` ou query; qualquer heurística de merge automático.
> 281	3. Contas nascem `email: tiktok_<open_id>@tiktok-login.mcorch.local`, **password-less/non-resettable**, namespaced ao domínio controlado (não roteável, não é um email real do titular → o titular não pode "reivindicar" a conta por email).
> 282	4. **Por quê:** auto-link ressuscitaria exatamente o vetor de grafting cross-tenant que `oauth-state.ts` foi criado para fechar (um atacante ligaria seu `open_id` à conta de uma vítima). O TikTok nem retorna email (map §Abordagem) — não há sinal legítimo para linkar. Link-to-existing **consentido** (com `auth.uid()` presente) é Could/deferido (PR-TL-009 · OTD-TL-010), **nunca automático**.
