# firecrawl scrape

Scrape one or more URLs. Returns clean, LLM-optimized markdown. Multiple URLs are scraped concurrently.

## When to use

- You have a specific URL and want its content
- The page is static or JS-rendered (SPA)
- Step 2 in the [workflow escalation pattern](firecrawl-cli): search → **scrape** → map → crawl → interact

## Quick start

```bash
# Basic markdown extraction
firecrawl scrape "<url>" -o .firecrawl/page.md

# Main content only, no nav/footer
firecrawl scrape "<url>" --only-main-content -o .firecrawl/page.md

# Wait for JS to render, then scrape
firecrawl scrape "<url>" --wait-for 3000 -o .firecrawl/page.md

# Multiple URLs (each saved to .firecrawl/)
firecrawl scrape https://example.com https://example.com/blog https://example.com/docs

# Get markdown and links together
firecrawl scrape "<url>" --format markdown,links -o .firecrawl/page.json

# Ask a question about the page
firecrawl scrape "https://example.com/pricing" --query "What is the enterprise plan price?"
```

## Options

| Option                   | Description                                                      |
| ------------------------ | ---------------------------------------------------------------- |
| `-f, --format <formats>` | Output formats: markdown, html, rawHtml, links, screenshot, json |
| `-Q, --query <prompt>`   | Ask a question about the page content (5 credits)                |
| `-H`                     | Include HTTP headers in output                                   |
| `--only-main-content`    | Strip nav, footer, sidebar — main content only                   |
| `--wait-for <ms>`        | Wait for JS rendering before scraping                            |
| `--include-tags <tags>`  | Only include these HTML tags                                     |
| `--exclude-tags <tags>`  | Exclude these HTML tags                                          |
| `-o, --output <path>`    | Output file path                                                 |

## Tips

- **Prefer plain scrape over `--query`.** Scrape to a file, then use `grep`, `head`, or read the markdown directly — you can search and reason over the full content yourself. Use `--query` only when you want a single targeted answer without saving the page (costs 5 extra credits).
- **Try scrape before interact.** Scrape handles static pages and JS-rendered SPAs. Only escalate to `interact` when you need interaction (clicks, form fills, pagination).
- Multiple URLs are scraped concurrently — check `firecrawl --status` for your concurrency limit.
- Single format outputs raw content. Multiple formats (e.g., `--format markdown,links`) output JSON.
- Always quote URLs — shell interprets `?` and `&` as special characters.
- Naming convention: `.firecrawl/{site}-{path}.md`

## See also

- [firecrawl-search](../firecrawl-search/SKILL.md) — find pages when you don't have a URL
- [firecrawl-interact](../firecrawl-interact/SKILL.md) — when scrape can't get the content, use `interact` to click, fill forms, etc.
- [firecrawl-download](../firecrawl-download/SKILL.md) — bulk download an entire site to local files

Não precisa de rede em runtime.

## 2. A regra que de fato governa: nominative fair use

### O teste (New Kids on the Block v. News America, 9th Cir. 1992)

Três condições cumulativas ([Wikipedia](https://en.wikipedia.org/wiki/Nominative_use), [Arnold & Porter](https://www.arnoldporter.com/~/media/files/perspectives/publications/2012/12/nominative-fair-use-legitimate-advertising-or-tr__/files/publication/fileattachment/nominative-fair-use.pdf)):

1. O produto/serviço **não é razoavelmente identificável sem usar a marca**;
2. Usa-se **apenas o quanto da marca for razoavelmente necessário** para identificar;
3. O usuário **não faz nada que sugira patrocínio ou endosso** do titular.

Um vídeo editorial comparando modelos de IA satisfaz (1) trivialmente — não há como falar de Claude sem dizer "Claude". O caso original era justamente uma **enquete de jornal sobre uma banda** — contexto editorial, o mais forte que existe.

### O ponto que decide o pedido do Sovereign: logo ≠ nome

**Toyota Motor Sales v. Tabari, 610 F.3d 1171 (9th Cir. 2010)** — li a [opinião primária do 9º Circuito](https://cdn.ca9.uscourts.gov/datastore/opinions/2010/07/08/07-55344.pdf) (PDF, 111,6 KB). A corte distingue o **nome** da **identidade visual**:

> os réus "could adequately communicate their message **without using the visual trappings of the Lexus brand**"

A corte notou que os Tabari usaram apenas a palavra "Lexus", **não o logo "L" nem a tipografia estilizada** — e que o uso desses elementos visuais "might lead some consumers to believe they were dealing with an authorized Toyota affiliate". O fator 2 do teste ("só o necessário") é exatamente onde o logo pesa contra você.

Sobre disclaimers, a corte foi clara:

> "Speakers are under no obligation to provide a disclaimer as a condition for engaging in truthful, non-misleading speech."

Disclaimer **não é obrigatório** — mas o disclaimer proeminente dos Tabari ("We are not an authorized Lexus dealer or affiliated in any way with Lexus") **ajudou** a defesa deles.

**Honestidade sobre o alcance:** Tabari era contexto **comercial** (revenda de carros). Conteúdo **editorial/jornalístico comparativo** — que é o caso do EP06 — é território muito mais forte, mais próximo do New Kids. Não estou dizendo que logo é proibido; estou dizendo que **o logo é o elemento que consome o fator 2**, e que a jurisprudência já sinalizou desconforto com ele.

**Nuance que importa e que costuma ser confundida:** as brand guidelines das empresas ("você precisa da nossa aprovação prévia") são declarações unilaterais do titular. Elas vinculam **licenciados e parceiros** por contrato. Elas **não extinguem** o nominative fair use para um terceiro que faz referência verdadeira e não-enganosa — nenhuma empresa pode, por política própria, revogar uma defesa legal. Mas elas **são evidência** do que o titular considera confusório, e é isso que as torna operacionalmente relevantes.

## 4. Gráficos de rank em motion — quando mentem e quando são honestos

### O que a referência canônica de design editorial prescreve

O [FT Visual Vocabulary](https://github.com/Financial-Times/chart-doctor/tree/main/visual-vocabulary) (equipe de Visual Journalism do Financial Times) define "Ranking" como família própria:

> "Use where an item's position in an ordered list is more important than its absolute or relative value."

Formas recomendadas para rank:
- **Ordered bar/column** — "display the ranks of values much more easily when sorted into order"
- **Dot strip plot** — eficiente em espaço para rank em múltiplas categorias
- **Lollipop** — "draw more attention to the data value than standard bar/column"
- **Slope chart** — "perfect for showing how ranks have changed over time"

⚠️ Licença: **© The Financial Times Limited, all rights reserved** — o pôster é referência de método, **não** asset reutilizável. Copiar o layout do FT é outro problema, e não é o que estou recomendando.

### Bar chart race — o veredito dos especialistas

Da compilação da [Built In](https://builtin.com/data-science/bar-chart-races):

**Contra:**
- **Andy Cotgreave** (Tableau): sobrecarga de informação — "It should have been a line chart"
- **Mike Bostock** (co-fundador do Observable, autor do D3): "the bar chart races you see on social media are typically **entertainment, not analysis**" — elementos em movimento dificultam extrair valores precisos, e um frame por vez esconde o padrão temporal
- **Estudo Robertson (2008)**: visualizações animadas produziram **leitura menos precisa** de valores, embora mais prazerosas

**A favor:**
- **Duncan Clark** (co-fundador do Flourish): superam line charts quando há muitas entidades — "a chart with 50 or 100 lines would be very messy"
- **John Burn-Murdoch** (FT): apropriado quando os valores mudam substancialmente, entidades entram/saem do ranking, ou o assunto é naturalmente competitivo

### Tradução para o EP06

| Forma | Quando é honesta | Quando mente |
|---|---|---|
| **Ordered bar / lollipop estático** | Rank num **instante** com fonte e data — o caso do EP06 | Se a escala não começa em zero |
| **Dot strip plot** | Comparar várias métricas do mesmo conjunto de modelos | — |
| **Bump / slope chart** | Mostrar **mudança** de posição entre duas datas | Se sugere continuidade onde só há 2 medições |
| **Bar chart race** | Séries longas, muitas entidades, valores que viram de fato | **Quase sempre, no caso de IA** — anima ruído estatístico e vende drama onde há empate |

**Recomendação:** o EP06 quer comparar modelos **hoje**. Isso é *ranking num instante*, não *mudança ao longo do tempo*. A forma correta é **ordered bar ou lollipop com logo no rótulo** — não bar chart race. E há um motivo estatístico decisivo, na seção 5.

## 5. Fontes de DADOS de rank — e por que "sem data e sem fonte" é mentira gráfica

| Fonte | O que mede | Cadência | Acesso |
|---|---|---|---|
| **[LMArena](https://arena.ai/)** (ex-lmsys.org; redireciona 301 para `arena.ai`) | Preferência humana em comparação pareada, modelo **Bradley-Terry** | Contínua | [arena-rank open source](https://github.com/lmarena/arena-rank) |
| **[Artificial Analysis](https://artificialanalysis.ai/)** | Intelligence Index v4.1 — 9 benchmarks: GDPval-AA v2, τ³-Banking, Terminal-Bench v2.1, SciCode, HLE, GPQA Diamond, CritPt, AA-Omniscience, AA-LCR | **Quase diária** | [API v2 grátis, 1.000 req/dia](https://artificialanalysis.ai/data-api) |
| **[SWE-bench](https://www.swebench.com/)** | Resolução de issues reais de GitHub (Verified / Lite / Pro / Multilingual / Multimodal) | Por submissão | Leaderboard público |
| **MMLU** | Conhecimento multitarefa | Estático | ⚠️ **saturado** |

### Três armadilhas que tornariam o gráfico do EP06 uma mentira

**(a) LMArena: a ordem do top-3 é frequentemente ruído.** A [metodologia oficial](https://arena.ai/blog/arena-rank/) confirma Bradley-Terry com "closed-form confidence interval calculation". O ponto prático: modelos do topo rotineiramente têm **intervalos de confiança sobrepostos** — dois modelos com Elo 1500±5 e 1502±8 estão **estatisticamente empatados** ainda que um apareça em #1 e o outro em #3. Desenhar um pódio 1-2-3 sem barra de erro **inventa uma diferença que os dados não sustentam.** É exatamente a família de defeito da "curva hardcoded" já corrigida na casa.

**(b) SWE-bench Verified está queimado — e a própria OpenAI parou de usá-lo.** ⚠️ *via índice de busca; a página `openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/` retorna 403 daqui, não li diretamente.* Os achados relatados: contaminação de 8–10%; modelos reproduzem verbatim gold patches; o framework UTBoost indica ~24% das entradas do Verified mal-pontuadas (~41% no Lite); auditoria de 138 tarefas difíceis achou 59% com falhas materiais. **A OpenAI teria parado de reportar SWE-bench Verified em fevereiro de 2026**, recomendando SWE-bench Pro. Citar SWE-bench Verified como rank atual no EP06 seria citar um benchmark que o próprio maior participante abandonou.

**(c) MMLU está saturado.** ⚠️ *via índice de busca.* Modelos de fronteira em ~90%+, agrupados numa faixa de menos de 2 pontos. O sucessor é **MMLU-Pro** (~12.000 questões, 10 alternativas), onde os scores caem 14–16 pontos e a dispersão volta a discriminar.

### A regra operacional

Como o Artificial Analysis atualiza quase diariamente (changelog mostrava "5 Aug" na véspera desta pesquisa) e o LMArena é contínuo, **um gráfico de rank de IA tem validade de dias.** Todo gráfico do EP06 precisa carimbar na tela:

```
Fonte: <nome> · Coletado em <YYYY-MM-DD> · <métrica exata>
```

O Artificial Analysis, aliás, tem a única API pública gratuita do conjunto (`https://artificialanalysis.ai/api/v2`, header `x-api-key`, 1.000 req/dia) — permite gerar o gráfico com **dado fresco e datado automaticamente**, em vez de número digitado à mão que envelhece em silêncio. Isso resolve o problema estruturalmente, não por disciplina.

## 6. Veredito e recomendação operacional

**Sobre logos:** usar logos reais num vídeo editorial comparativo é **defensável** sob nominative fair use — é a hipótese clássica do New Kids. Mas Toyota v. Tabari deixou registrado que a **identidade visual** ("visual trappings") é o que consome o fator 2 do teste, e todas as guidelines legíveis proíbem recolorir, distorcer e sugerir afiliação. Não é caminho bloqueado; é caminho com regra estreita.

Postura de menor risco, que é também a de melhor design:

1. **Asset oficial, sem modificação.** Baixar de brand page (`cdn.openai.com/brand/OpenAI-Logos-2025.zip`, `mistral.ai/brand`, `huggingface.co/brand`) em vez de agregador. Simple Icons/svgl servem para *descobrir* e para marcas sem brand page; a fonte canônica é a oficial.
2. **Nunca recolorir, esticar, rotacionar ou animar o logo em si.** O logo entra e sai (opacidade/posição); a *forma* dele não se deforma. Isso é compatível com o design system de motion já selado — e satisfaz as 5 proibições comuns.
3. **Logo só no rótulo do dado**, ao lado do nome do modelo. Nunca dentro do lockup MCORCH, nunca com proeminência maior que a marca da casa (regra explícita da OpenAI).
4. **Card de fonte + data em toda cena de rank**, e barra de erro (ou empate declarado) quando o intervalo de confiança sobrepõe.
5. **Disclaimer de não-afiliação** na descrição do episódio. Não é obrigatório (Tabari), mas foi o que ajudou a defesa lá.
6. **OpenAI merece cuidado extra** — é a única das marcas citadas que um projeto profissional removeu do acervo por falta de permissão, e cujos termos reservam revogação a qualquer tempo.

**Sobre gráficos:** o EP06 quer rank *num instante* → **ordered bar / lollipop com logo no rótulo**, não bar chart race. Bostock é direto: race é entretenimento, não análise; e no caso de IA ela animaria empates estatísticos.

**Sobre engenharia:** as duas capacidades (embed de SVG real e gráfico de rank preciso) convergem numa só primitiva no motor — **renderizar geometria vetorial arbitrária vinda de dados, inline e offline**. O `ICON_LIBRARY` já é exatamente isso, só que com um dicionário fechado de 20 glifos genéricos casados por keyword. A extensão natural é um registro de assets versionado (SVG inline + proveniência: URL de origem, data de download, licença/guideline) que serve tanto o logo quanto o rótulo do gráfico. Custo USD 0, sem rede em runtime, determinístico — compatível com `sceneSeed`.

**Não verificado, declarado:** `openai.com/brand`, `x.ai/legal/brand-guidelines`, `duetsblog.com` e `web.archive.org` retornaram 403/indisponível deste host (Cloudflare, IP de datacenter Oracle); `vectorlogo.zone/faq` retornou 404. Claims marcados ⚠️ vêm de índice de busca ou de citação de terceiros. Recomendo confirmar OpenAI e xAI pelo Chrome do Sovereign antes de qualquer decisão que dependa do texto exato dessas duas.

**Nada aqui é aconselhamento jurídico.** O uso comercial de marcas alheias em conteúdo monetizado merece revisão de um advogado antes de publicar — especialmente porque o canal é monetizado e o vídeo promove um produto da casa, o que enfraquece o enquadramento puramente editorial.
