That inverse is where the only real nuance lives, and it is a **LOW/informational** observation, not a finding:

- The channel check only catches `email` (the regex token `e-?mail`). The system-prompt's other outward channels — `social`, `affiliate` — do **not** match the regex (`"social"`, `"affiliate"` contain none of the tokens). So channel-based detection alone would not flag a `social`/`affiliate` task.
- The genuine safety net is therefore the **`action` verb regex** (`publi|send|post|tweet|spend|charge|cobr|envi|dispar|whats|launch|lança|…`, case-insensitive, covering EN+PT) **plus the AI's own `impact` label**. For an outward action to escape, the LLM would have to (a) self-label it `low`/`medium` AND (b) phrase the action verb with zero high-impact tokens in either language. Given the system prompt explicitly instructs `impact=high para publicar, enviar, cobrar ou veicular anúncio`, a *cooperative* model won't do this; a fully *adversarial* model output could in principle, but per point (1) the only consequence is a persisted `auto_approved` row — the downstream executor (future) is the actual enforcement boundary and must re-validate before any outward action.

**Recommendation (non-blocking, defense-in-depth for the future executor):** when the execution/approval step is built, it must NOT trust `intent_plans.status='auto_approved'` as a license to send — it should re-run an outward-action check at execution time. Optionally, add `social` and `affiliate` to the channel side of `HIGH_IMPACT_RE` (or, better, treat any non-`none`/non-`content` channel as outward) so channel alone forces HITL regardless of the action verb. Neither is required for this PR since nothing executes here.

## 3. AI output handling — PASS (no injection / RCE / crash)

`intent-orchestrate/index.ts:73-85`: `raw.match(/\{[\s\S]*\}/)` extracts a brace-delimited substring, then `JSON.parse(match[0])` runs inside the surrounding `try { … } catch (_) {}` (lines 53-86). 

- `JSON.parse` is data-only — no `eval`, no `Function`, no template execution. There is no RCE surface.
- A malformed string either fails `.match()` (→ `match` null → skip) or throws in `JSON.parse` → caught → `tasks` stays `[]` → heuristic fail-soft. Worst case is a heuristic single-task plan, exactly as designed.
- Every field is defensively coerced and length-capped before persistence: `String(t.action ?? "task").slice(0,120)`, channel `.slice(0,40)`, `impact` whitelisted against `["low","medium","high"]` with a `"medium"` default, rationale `.slice(0,300)`, and `tasks.slice(0,5)` caps array size. A hostile AND well-formed JSON payload (e.g. 10⁶ tasks, or a 1 MB action string, or `impact:"__proto__"`) is truncated/whitelisted — no prototype-pollution sink (values are read, never used as keys), no unbounded growth. This matches the `lead-score` parse hardening (lines 120-128) and is actually more thorough.
