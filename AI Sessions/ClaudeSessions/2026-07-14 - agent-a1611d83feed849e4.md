## NO FINDINGS

No high-confidence (≥8) exploitable vulnerabilities in the new `authenticate()` / `serveMedia()` code.

**Verdict per hunt area:**

1. **Path traversal (serveMedia) — SAFE.** `key` is percent-decoded once by `URLSearchParams`, then `.includes('..')` runs on that decoded string, so `%2e%2e%2f` → `../` is caught; double-encoding (`%252e`) never gets a second decode, so it stays a literal filename segment that the FS won't treat as traversal. Null bytes make `existsSync` throw→false→404. Backslashes are ordinary chars on Linux. `key` must `startsWith(`${userId}/`)` (a fixed-length UUID) AND contain no `..`, so the resolved path can never climb out of `INBOX_BASE/<callerUid>/`; the `resolve().startsWith(INBOX_BASE + '/')` guard (trailing slash present → no `inbox-evil` prefix trick) is a correct backstop. `resolve()` (lexical) is sufficient vs `realpathSync` because the upload route only ever `createWriteStream`/`renameSync` regular files under sanitized names — it never creates symlinks, so there is no attacker-plantable symlink to follow (line 85–88).

2. **Auth / query-token fallback — SAFE.** `authenticate()` runs before method dispatch and enforces the admin gate on every route (401 no-token, 401 bad-JWT, 403 non-admin) for both GET and POST (line 116–117). The `?token=` fallback presents the *same* bearer credential — it grants no new privilege and enables no CSRF, because the JWT is not an ambient cookie (a cross-origin page cannot place the victim's token into the request). POST-with-`?token=` still requires a valid admin JWT. *Noted, not flagged:* the session JWT lands in nginx access-log query strings (`Cache-Control: private, no-store` prevents body caching but not URL logging). Real but low severity given admin-only, single-tenant, same-origin TLS, ~1h TTL — well below 8.

3. **Cross-tenant read — SAFE.** `key.startsWith(`${userId}/`)` binds every read to the *caller's own* UUID dir; UUIDs are fixed 36-char so no UID is a `/`-prefix of another, and `..` is banned, so an admin cannot reach another uid's inbox (line 85).

4. **Header injection / response smuggling — SAFE.** `Content-Range`/`Content-Length` are built only from integers (`parseInt`, `statSync().size`); `Content-Type` is one of two literal strings; the `Range` header is gated by the strict `^bytes=(\d*)-(\d*)$` regex (digits only). `key` is never reflected into any response header. No CRLF-injectable path (line 90–104).
