**Keyframes:** `mc-node-ring-spin` (o anel girando) + `mc-pulse-glow` (o glow pulsante). Property CSS custom `--mc-spin` (`@property`, tipo `<angle>`).

### Onde é definido (CSS)
`src/index.css:253-293` — bloco "Amendment 19 — Spaces canvas motion design". O efeito é composto de **duas partes**:

1. **Glow pulsante** no próprio card — `src/index.css:262-265`
   ```css
   .mc-node-processing {
     border-radius: 0.5rem;
     animation: mc-pulse-glow 1.8s ease-in-out infinite;
   }
   ```
   `mc-pulse-glow` (`src/index.css:172-175`) alterna `box-shadow` cyan de 12px→26px.

2. **Anel de energia que CIRCULA a borda** — `src/index.css:272-293`, pseudo-elemento `::before` com `conic-gradient(from var(--mc-spin), …)` mascarado (`-webkit-mask` + `mask-composite: exclude`) para virar só borda. O gradiente cônico gira via `animation: mc-node-ring-spin 1.6s linear infinite` (`src/index.css:259-261`, que anima `--mc-spin` de 0→360deg). Cor NEON = cyan `#00f2ff` / `rgba(0,242,255,…)`.

Detalhe de acabamento: a borda estática do card é escondida enquanto processa para não ler como "segunda borda" sob o anel — `src/index.css:269-271` (`.mc-node-processing > div:not(.ring-2) { border-color: transparent; }`).

Estados irmãos no mesmo bloco: `.mc-node-failed` (`src/index.css:307-310`, shake + glow vermelho), e edges `.mc-edge-transmitting`/`.mc-edge-established` (`src/index.css:313-324`).

### Onde é aplicado (TSX)
A classe **não vem de um componente de nó** — os nós individuais (`GenerateImageNode.tsx` etc.) só mostram o spinner `Loader2 animate-spin` + um `StatusBadge`. O anel NEON é injetado no wrapper do ReactFlow pelo container do canvas:

- `src/pages/CanvasEditorPage.tsx:97` — `const NODE_BUSY = new Set(["queued", "running"]);`
- `src/pages/CanvasEditorPage.tsx:98-102` — `nodeMotionClass(data)` retorna `"mc-node-processing"` quando `NODE_BUSY.has(data.status)`, `"mc-node-failed"` quando `failed`.
- `src/pages/CanvasEditorPage.tsx:287-293` — `motionNodes` mapeia cada nó e injeta `{ ...n, className: cls }` (derivado do estado REAL, nunca persistido no graph).

**Gatilho de status:** `status === "running"` **ou** `"queued"` (ambos no `NODE_BUSY`), não apenas "running".

### Guarda de acessibilidade
`src/index.css:328-337` — `@media (prefers-reduced-motion: reduce)` zera todas essas animações (`animation: none !important`).

---

### Para REUSAR num card de kanban
A classe `.mc-node-processing` é global (definida em `src/index.css`, carregada em toda a app) e **auto-contida**: depende só de `position: relative` + `overflow` no elemento-alvo (o `::before` usa `inset: -2px`, então o alvo não pode ter `overflow: hidden` cortando o anel — repare que os nós usam `overflow-hidden` no card interno mas o wrapper do ReactFlow não). Basta aplicar `className="mc-node-processing"` (com `position: relative`) num card cujo `border-radius` seja `0.5rem` (`rounded-lg`) para o anel abraçar as bordas. Nenhum JS/prop extra necessário — é 100% CSS. As cores são hardcoded cyan `#00f2ff`; não usa variável de tema, então o NEON fica cyan em light e dark igual.

Um caveat material para o kanban: o pseudo-elemento fica em `z-index: -1` (`src/index.css:276`), então o card precisa de um `background` opaco próprio e um stacking context onde `-1` não suma atrás do fundo da coluna — nos nós funciona porque o wrapper ReactFlow cria o contexto. Num card de kanban simples pode ser preciso trocar para `z-index: 0` + `content-box` ou envelopar, senão o anel some sob o fundo.
