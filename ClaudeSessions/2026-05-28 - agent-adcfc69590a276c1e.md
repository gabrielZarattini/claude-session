   - Canvas-execute inserts execution (line 265) WITHOUT `input_asset_url` field.
   - Webhook finalize queries execution but cannot retrieve the input image URL from the execution row.
   - **Contract gap:** Frontend sends `input_asset_url` in request, but backend does not store it in `vm_canvas_executions`. Webhook has no way to record which image was used.

2. **input_asset_url is not optional at runtime but optional in request type:**
   - `ExecuteRequest.input_asset_url` is `?: string` (optional type).
   - `submitHiggsfieldVideo()` line 933 validates `if (!imageUrl)` → **requires it or fails with 400**.
   - **Contract gap:** Type says optional, code says required. If frontend sends request without it, validation fails, but execution record is already created. No atomicity.

3. **Execution record creation happens BEFORE input_asset_url validation:**
   - Line 263–280: Execution inserted with only node_id, node_type, provider, model, prompt (NO input_asset_url).
   - Line 409: Later checks `if (body.node_type === "image_to_video")` → calls submitHiggsfieldVideo().
   - Line 932–937: submitHiggsfieldVideo validates input_asset_url; if missing, fails.
   - **Contract gap:** If input_asset_url is missing, execution row is marked "queued" but submission fails. No atomic rollback. Execution appears in DB with null input asset, triggering mystery of 87654829.

4. **No cost-key validation for durations not in CREDIT_COSTS map:**
   - Cost key constructed as `${provider}/${model}-${duration}s` (line 158).
   - If request has `duration: 10`, key becomes `"higgsfield/dop-lite-10s"` → not in map → defaults to 10 credits.
   - **Contract gap:** Backend accepts any duration in parameters; cost is a silent fallback, not validated. User could request `duration: 120` and only be charged 10 credits.

5. **node_type=generate_video and node_type=image_to_video branching confusion:**
   - Request uses `node_type: "image_to_video"` for routing (line 409).
   - Database enum stores `"generate_video"` after mapping (line 269).
   - **No text-to-video branch** (all videos require image input).
   - **Contract gap:** The name mismatch (`image_to_video` vs `generate_video`) is confusing. Database enum forces a translation, but no comment explains why both exist.

6. **input_asset_url not recorded in asset rows:**
   - Canvas-execute inserts image assets (line 504) without `input_asset_url`.
   - Webhook inserts video assets (line 201) without source image reference.
   - **Contract gap:** No way to reconstruct which input image was used to generate a given video. Asset lineage is lost.

7. **No enforcement of image_to_video tier names in cost key lookup:**
   - ALLOWED_VIDEO_MODELS validation (line 227) checks model is in the list.
   - But cost lookup (line 158) constructs key **`${provider}/${model}-${duration}s`** without enforcing `model` matches a key in CREDIT_COSTS.
   - **Contract gap:** Backend validates model name syntactically but does not validate cost-key existence. If cost key is missing, default 10-credit cost is used silently.

8. **Webhook does not record input_asset or input_asset_id in asset row:**
   - Video asset inserted (line 201) with no field linking back to the source image.
   - **Contract gap:** Frontend graph cannot trace which image → video edge was used to generate an asset. Only the execution row has node_id, not the asset row.
