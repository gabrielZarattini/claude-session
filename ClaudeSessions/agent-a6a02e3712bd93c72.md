## Decision rationale

### Q1 — Authoring method: manual targeted authoring

`/bok-scribe` (`.claude/commands/bok-scribe.md` → `.claude/agents/bok-scribe-agent.md`) is designed for **greenfield** generation: Phase 0 derives a slug, creates the directory, and renders ALL 9 docs in strict sequence, each reading the previous. Its guardrail for an existing directory is "show index, ask: overwrite / extend / cancel" — but the agent has no surgical "fill only the 6 gaps" mode. Running it here risks:
- Overwriting the high-quality existing `03-prd.md` (829 lines) and `05-sdd.md` (1717 lines).
- Re-deriving Phase 1-3 content from scratch, producing MRD/BRD that don't align with the *already-written* PRD/SDD vision (the agent generates forward MR→BR→PR; here PR already exists and the MRD/BRD must be reverse-traced *backward* to match it).
- The agent cannot ground itself in the shipped `vm_*` migrations — it works from the business idea, not the codebase.

Manual authoring lets us: (a) preserve the 3 good docs untouched, (b) reverse-engineer MR/BR IDs that trace cleanly *into* the existing PR IDs, (c) ground every doc in the actual 4 migrations + 2 edge functions + frontend, and (d) apply the conteudo-v2 Appendix pattern deliberately. This is exactly how conteudo-v2's own `06-data-model.md` §8 appendix and `00-index.md` Convergence Note were done — manually, post-hoc.

### Q2 — Scope/voice: vision-level with a v1 Reality appendix

The existing `03-prd.md` and `05-sdd.md` describe the **grand 5-module vision** (Viral Miner, Canvas Studio, Video Factory, Affiliate Radar, Ads Commander). If the 6 new docs documented *only what shipped*, the suite would be internally contradictory — a PRD promising 5 modules and an MRD/BRD scoped to 2.5. The MCORCH BoK philosophy (per the agent definition and the conteudo-v2 precedent) treats the BoK as the **roadmap of evolution**, not a snapshot. conteudo-v2's `06-data-model.md` §8 says this explicitly: *"este BoK passa a ser o roadmap de evolução (Phase 4-8) com tabelas adicionais ainda por criar."*

So: each new doc is **vision-level in its main body**, then carries a clearly-marked closing section that reconciles plan vs. shipped. Concretely per doc:
